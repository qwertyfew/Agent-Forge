## 三个当场发现并已修复的问题

### 1. webui 事件白名单丢了 warmup 播报（显示 bug，已修 `22ec9e8`）

rerun8 全程无 warmup 事件，排查确认**注入本身在服务端正常生效**（orchestrator 把
warm_block 挂进每个员工的系统提示，不经过 webui），被丢的只是通知事件——webui 的
if/elif 转发链没有 `warmup` 分支。补上透传，rerun9 胶囊提示正常亮出。

### 2. gpt-oss 任调度模型后规划/评估 8 连败（核心修复 `30dd5d4`）

rerun8 每一轮「规划失败→退回全文兜底→评估失败→重排」，12 轮全部烧在兜底循环。
直连 Ollama API 复现定位到两个叠加根因：

- `num_predict=2048` 被思考通道吃掉大半：gpt-oss 的 analysis token 与正文**共享生成
  预算**，真实规划提示词下正文只吐 428 字符就在 JSON 字符串中间截断；
- `think=False` 更糟：Ollama 对 gpt-oss **并不真正关闭思考**——analysis 照常生成却不
  进 content（reasoning 字段也是空的，纯烧掉），且提前 `done_reason=length`。

修复：`think=True`（harmony 正常通道，final 才是正文）+ `num_predict=8192` + 空响应
重试一次。离线同提示词 3/3 解析出 2–3 个子任务/批，评估调用同步受益。

### 3. 引用守卫被「带行号的圆括号引用」绕过（已修 `61a5881`）

rerun9 交付物的引用几乎全是 `(learn-claude-code/s01_agent_loop/code.py:96-127)` 形态。
抽取器的形状校验只认「末段带扩展名」，`:96-127` 尾巴被整份拒收 → **checked=0 → 写盘
审计根本没跑**（与 rerun7 的圆括号绕过同类，守卫与模型写法的持续对抗第二回合）。
修复后同一份文件 checked=6、硬错误=4（漏写 `external/` 前缀，全部命中可复现修正提示
「实际在 external/learn-claude-code/...」），会在写盘前被拦。全角括号引用一并补上。

## 遗留问题（按优先级）

1. **长上下文下 gpt-oss 规划/评估仍会解析失败**（r4 起复发，r4–r12 规划 9 连败）。
   疑似上下文增长后思考 token 继续膨胀、8192 仍不够或空 final。当前 `_chat` 失败时
   原始输出不落盘，无法判定截断还是空——**下一步先给 `_chat` 加失败原始输出落盘
   （done_reason/eval_count/content 尾部），再对症**。
2. **兜底循环浪费轮次**：规划失败时整轮退回全文兜底，员工跑完却因「交付物 stale」
   被验收打回，12 轮耗尽。可在规划连续失败 N 次后降级为「规则拆解」而非每轮重试。
3. **交付物中途版本落盘**：rerun9 把 rerun7 的高质量版本覆盖成 7/10 对比点的弱版本
   （缺子代理、评测体系、会话恢复三节；AgentForge 侧引用无行号）。旧版在 git
   （1a95424）可恢复；建议任务写交付物前若文件已存在先备份到 history/。

## 结论

三项本日改动中，预热注入与角色分工的**机制**都验证成立（注入量化生效 +1873 tokens；
gpt-oss 在短上下文下规划/评估质量高于 gemma），但 **gpt-oss 长上下文稳定性**是当前
链路的最大短板，需要观测补齐后再跑 rerun10 验证。
