# rerun27 评测：闸门装上了，但它们互相锁死

**日期**：2026-10-20
**任务**：与 rerun26 完全一致（逆向 `external/mini-swe-agent` + `external/learn-claude-code`，产出
`evals/external-harness-gap-list-rerun27.md` 逐项差距清单）
**结论一句话**：交付物 **0 字节**（文件不存在），任务状态 `error`（未交付硬闸首次真正生效）；
失败原因不是模型不动手，而是**三处程序缺陷把模型锁在「读了也白读」的循环里**。

---

## 1. 结果

| 指标 | rerun26 | rerun27 |
|---|---|---|
| LLM 轮次 | 7 | 12（3 次 run：9 轮 + 2 轮 + 1 轮） |
| 工具调用 | **0** | 8（全是 ops_batch，脚本内共 93 次只读调用） |
| 交付物 | 不存在 | **不存在** |
| 任务台账状态 | `done`（假成功） | `error`（`任务未交付：evals/external-harness-gap-list-rerun27.md`） |
| 用户可见结论 | 「下一步计划」 | 末尾仍是「核实完成后将立即完成写入」 |

温度 1.0→0.5 的收益是实的：模型从「一个字都不动手」变成真读了一百来个文件位置、真写了两次交付物。
**但两次写都被核查拒绝，第三次被写前门槛拒绝，之后轮次耗尽。**

## 2. 三处根因（都在程序侧，不在模型侧）

### A. 证据台账按「轮」重置，而取证是「任务级」动作 —— 致命

`loop.run()` 开头 `self.guard.ledger = EvidenceLedger()`。修正轮也是「一次 run」，
于是第一轮读过的 50 个文件，在第二轮写交付物时全被判成「本任务从未 read_file 过」：

```
write_file → 引用核查未通过：引用了本任务从未 read_file 过的文件:
  external/learn-claude-code/s07_skill_loading/code.py
write_file → 写前检查未通过：这份内容引用了 19 处项目内文件，但本任务一次 read_file 都没有
```

模型照做（又读一遍），第三轮重置再忘一次。**新加的写前门槛把原本只是「引用被拒」的问题
升级成了「整篇被拒」，死锁闭环就此形成。**

### B. 未交付硬闸的豁免判据是「试过写」，不是「写成功过」

`untouched = not produced_possible(convo)`，而 `produced_possible` 只看轨迹里出现过
写类调用（含 PTC 脚本源码匹配）。两次写入**全部失败**，豁免仍成立，硬闸本该哑火——
实际是被台账缺陷引爆后才在 `deliverable 复核` 阶段拦下（`status=missing` + `wrote_ok` 缺位）。
判据必须换。

### C. ops_batch 只吃一个位置参数

`call('write_file', path, content)` → `write_file() 最多 1 个位置参数` → 白烧一轮。
这是同一个接口摩擦的第二次复发（rerun23/24 各一次）。

## 3. 修法

| 缺陷 | 改动 | 文件 |
|---|---|---|
| A 台账跨轮 | `run(..., ledger=None)`：传入则沿用，不传才新建；`_verify_gate` 取首轮台账并传给全部 5 个修正轮；多步任务建 `task_ledger` 贯穿所有步骤与重跑 | `agentforge/loop.py`、`agentforge/orchestrator.py` |
| B 豁免判据 | 新增 `verify.wrote_ok(convo)`：按 tool_calls↔tool 回执顺序配对，回执带 `[错误]/[已拒绝]/未写入/写入失败` 的不算写成功；`run_command` 与「有调用无回执」从宽 | `agentforge/verify.py`、`agentforge/orchestrator.py` |
| C 位置参数 | `_with_positional` 按工具必填参数声明顺序逐个映射（write_file→path,content；edit_file→path,old_text,new_text），超额仍报错 | `agentforge/tools/ops.py` |

### 为什么 A 用「传入」而不是「不重置」

重置的本意是「避免跨任务串味」。同一个 Agent 实例会被多个请求复用，
无条件保留会让任务 B 继承任务 A 的「已读清单」，引用核查形同虚设。
所以台账归属由调用方声明：任务级创建、跨轮传递、任务结束即丢弃。

## 4. 新增断言

- `test_verify_gate`：写失败回执→仍判未交付；权威块确认写入→不判未交付；修正轮拿到同一份台账（3 条）
- `test_ops_batch`：`write_file` 两位置参数正确映射并落盘；超额位置参数明确报错（3 条）

全量回归：**39 通过 / 4 预存失败**（`ambiguity_gate`、`evalsdesk`、`multipath`、`service_ctrl`，
与本次改动无关，改动前已复验）。

## 5. 遗留

1. `done` 事件仍是空对象——状态只在 `notify` 与任务台账里，SSE 订阅方（含派发脚本）拿不到。
   属可见性问题，不是判定问题。
2. 写前门槛的措辞在「确实读过但台账丢了」时误导（说「一次 read_file 都没有」）。A 修好后不再触发，但
   提示语仍应区分「没读过」与「读过但没记账」。
3. 轮次预算：本轮 12 次 LLM 调用撞上限，第三次 run 只跑了 1 轮。修正轮与主循环共享预算这一点没变。

# rerun28 复验：交付通了，但「证据」这一栏是空的

## 6. 机制层面：修复生效

| 检查项 | rerun27 | rerun28 |
|---|---|---|
| 交付物 | 不存在 | **2885 字符，已落盘** |
| 任务状态 | error（未交付） | done（真实交付） |

| 核查拒绝次数 | 3 次（引用 2 + 写前 1） | **0 次** |
| 骨架先行 | 未使用 | 用上了（1 次拿 12 个写调用，同一轮完成） |

台账跨轮共用是这轮能通的关键：第一轮读的 50 来个文件，在后续写交付物的轮次里仍然算「读过」，
引用核查与写前门槛不再双重误杀。

## 7. 交付物质量：只过了一半

用一个独立核查器（`debug/check_deliverable.py`）把清单里每条引用回源核对：

| 维度 | 结果 |
|---|---|
| 引用路径真实性 | 28 处引用，**0 处文件不存在**（比 rerun23 的「路径全对、结论全错」进步在：这次没有编造路径） |
| 证据行号 | 28 处引用，**带行号的 0 处** —— 任务书硬性要求「附证据：仓库/文件/行号」，实际只写到文件级 |
| 证据层次 | 对方做法全靠 `README.md` / `AGENTS.md`，没有一条落到 `.py` 的代码行 |
| 十项维度覆盖 | 10/10 全中 |
| 借鉴清单 | 有，5 条，含预期收益与改动面 |
| 格式正确性 | 「会话恢复」一行**两列填反**（对方做法列写成了 AgentForge，AgentForge 列写成了 learn-claude-code） |
| 结论力度 | 全是「可考虑/可借鉴」，没有一条能量化差距——恰是任务书禁的「泛泛架构报告」 |

抽查两条实质结论：`context.py 两级压缩（截断与摘要）`**正确**（该文件头部就写着 L1 截断 / L2 摘要）；
`learn-claude-code 尚未体现会话恢复`**站不住**（`agents/s07_task_system.py`、`s12_worktree_task_isolation.py`
都有 resume 相关实现，没查到就写「没有」）。

结论：**流程健康、交付真实、证据不合格。** 相比 rerun26 的「零交付 + 假成功」是根本性进步，
但离任务书要求的「逐项差距清单」还差一层——现在的产物是架构总结，不是有代码行支撑的差距对照。

## 8. 这轮暴露的新问题：骨架被整节替换掉

模型把整张表当成一个 `## 对比点清单` 小节，逐行调用 `fill_section(默认 replace)` 十一次：
每次回执都「成功」，但每次都在**整体替换**这一节，前十行全被后一次覆盖。文件只剩一行表头 + 一行数据，
模型察觉后干脆整篇 `write_file` 重写，骨架先行的收益归零（12 次写调用只换来一次覆盖式重写）。

修法（本轮已改）：`fill_section` 是 replace 时，回执必须说明「整节替换」；文件没有变长时直接警告
「同一节第二次 replace 会丢掉上一次填的内容，逐行追加请用 mode='append'」；工具说明同步写清 replace 语义。
