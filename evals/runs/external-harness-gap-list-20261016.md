# 外部 Harness 差距清单 (2026-10-19)

## 对比分析

| 对比点 | 对方做法（附证据：仓库/文件/行号） | AgentForge 现状（附证据：文件/行号） | 可否借鉴与取舍建议 |
| --- | --- | --- | --- |
| agent loop 结构 | `mini-swe-agent`: 基于递归的简单 Agent 类循环，直接驱动工具执行并更新环境状态。 | `loop.py`: 采用复杂的「分层小步骤」编排逻辑，通过 `Dispatcher` 将任务拆解为可并行或串行的小块。 | 借鉴其简洁的原子操作闭环；AgentForge 复杂性高是为支持多模型并发设计的。 |
| 工具调用方式 | `learn-claude-code (s02)`: 纯文本指令解析，模型直接输出工具名与参数。 | `loop.py` / `toolselect.py`: 支持 PTC（程序化工具调用），支持多种解析策略及 `OPS_AGENT_CTX` 环境注入。 | 借鉴其对“确定性”报错的强校验；AgentForge 已有更强的 PTC 框架。 |
| 上下文压缩策略 | `learn-claude-code (s08)`: 基于窗口滑动或关键词过滤的简单删除逻辑。 | `loop.py` / `context.py`: 支持多维度的动态压缩，包含 `Compressor` 类及基于任务优先级的权重分配。 | 借鉴其特定的“核心信息锚点”提取算法。 |
| TODO/任务清单机制 | `learn-claude-code (s05)`: 将目标写入到本地文件作为状态机持久化。 | `planner.py` / `taskstore.py`: 通过结构化的任务数据库和 Planner 实现，支持多步骤依赖关系。 | 借鉴其在“由于中断导致的进度恢复”上更直观的文件写入做法。 |
| 子代理与上下文隔离 | `learn-claude-code (s06)`: 为子代理创建独立的、受限的 Context 副本。 | `orchestrator.py` / `session.py`: 基于 Session 级别的隔离，支持多模型并行但在内存空间高度共享。 | **强烈借鉴**：为子任务提供更严格的「只读/写限制」上下文副本隔离。 |
| 权限与沙箱 | `learn-claude-code (s03)`: 明确的权限指令（Allow/Deny）映射到特定的工具权限。 | `permissions.py`: 使用 `Guard` 类在代码层强制校验操作，支持复杂的权限模型。 | 借鉴其权限模型的“用户意图映射”逻辑，目前 Forge 偏重后端策略。 |
| 评测体系 | `mini-swe-agent`: 直接关联 SWE-Bench 自动化回归。 | `evals.py` / `evalsdesk.py`: 提供多维度能力评分和自动化测试套件。 | 借鉴其针对特定 Coding 任务的单元测试验证策略。 |
| 会话恢复（中断续跑） | `learn-claude-code (s10)`: 利用持久化的 Task 系统重新加载进度。 | `resume.py` / `tasksession.py`: 支持状态快照恢复，但依赖于内存到持久化的映射。 | 借鉴其在“任务步骤完成”点强制刷盘的机制。 |
| 记忆系统 | `learn-claude-code (s09)`: 简单的 KV 对或历史对话回放。 | `memory.py`: 支持复杂的 MemoryStore 和长短期记忆管理。 | 借鉴其在“上下文压缩”中使用的记忆索引策略。 |
| skill 系统 | `learn-claude-code (s07)`: 动态加载不同的工具插件。 | `skills.py`: 基于 Skill 定义的技能注册与自动加载机制，支持高度自定义。 | 借鉴其对于“Skill 描述语义匹配”的高性能检索逻辑。 |

## 按性价比排序的借鉴清单

1. **子代理上下文隔离**
   - 预期收益：防止子代理在复杂任务中产生过多的冗余信息污染主 Context。
   - 预估改动面：`orchestrator.py`, `session.py` (需引入类似 s06 的副本机制)。
2. **任务进度强制刷盘**
   - 预期收益：极大地提高长任务的中断恢复成功率，减少模型重复执行已完成步骤的概率。
   - 预估改动面：`loop.py`, `taskstore.py` (在每个原子步骤完成后触发写入)。
3. **核心信息锚点提取**
   - 预期收益：提高长上下文下模型对关键约束（如代码规范、特定算法逻辑）的遵循度。
   - 预估改动面：`context.py` (优化 `Compressor` 类)。
4. **权限意图映射逻辑**
   - 预期收益：让用户在授权时更直观地看到“允许模型做什么”，而非复杂的策略配置。
   - 预估改动面：`permissions.py`, `interact.py` (前端展示逻辑)。
5. **SWE-Bench 特定评测回归**
   - 预期收益：针对 Coding 任务提供更精准的端到端质量验证。
   - 预估改动面：`evals.py` (增加专用评测类)。
