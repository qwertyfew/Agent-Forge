# AgentForge

本机运行的 AI Agent Harness：用 Ollama 上的本地模型（可选接入付费 API）执行真实任务——
读写文件、跑命令、联网检索、SSH 远程运维、写长篇小说，甚至给自己写新工具和 Skill。

前端是零依赖的单文件页面（`web/index.html`），后端是纯标准库的 HTTP 服务（`webui.py`），
没有重框架、没有构建步骤，`git clone` 后装三个依赖就能跑。

## 特性

- **多模型与自动分配**：为每个模型打八维度能力分，任务按维度贪心挑选最优组合（可限定只用本地模型）。
- **多 Agent 调度（小步骤分配）**：本地「决策模型」把请求拆成**按能力类型分层的小步骤**
  （检索 / 代码分析 / 编码 / 写作各自成任务），每一步交给勾选模型中该维度最强的那个、
  维护共享进度接力交接；互不依赖的步骤并行波次执行（本地模型串行硬规则防显存互挤，
  同文件写入串行保护）。决策模型只做拆解/指派/交接和几句简单对话；拆解失败自动回退规则编排。
- **本地优先**：默认全部走 Ollama 本地模型，零 API 费用；付费模型（DeepSeek / SiliconFlow）按需勾选启用。
  Ollama 挂了会自动拉起（桌面版优先，退回 `ollama serve`），判定标准是「真能应答」而非「进程生出来了」。
- **Web 服务常驻**：双击一次 `start.bat`（Windows）/ 跑一次 `./scripts/start.sh`（Linux、macOS）就够了——
  它建好虚拟环境、登记开机自启，再起一个**无窗口**的保姆进程：端口没人服务就补位拉起，
  只补位不抢占、不杀进程（跑着任务时重启的代价远大于等它自己好）。
  服务本身不占任务栏、没有窗口可以误关，开机自启也随之装好——换台机器 clone 完即可复现。
- **点一下就到位**：侧栏的工作区路径、回复末尾的产出文件卡片，点一下就用系统默认程序打开，
  并把窗口**直接带到前台**。Windows 默认不许后台进程抢焦点，所以「打开」之后还得再点一次任务栏
  才看得见——`agentforge/reveal.py` 替它借一次前台资格、用完立刻还回去，省掉那一步。
- **任务台账**：每个任务记录状态、耗时、token 与预估费用、产出文件、对话历史，重启后自动把遗留的
  「执行中」标记为已中断。
- **会话恢复（断点续跑）**：被中断的任务不用从头重跑——回看页点「恢复执行」，从台账取回
  对话历史、修复中断缝隙（悬空工具调用如实标注「结果未知」），模型从中断处接着干；
  已完成的部分先核实再续做，不重复劳动。
- **产出追踪**：写文件工具精确记录；命令副作用靠任务前后工作区快照对比兜底——但只在**本任务确实
  动过手**（调过写类 / 命令类工具）时才去扫。纯问答任务不会被算上「任务跑着的时候别人顺手改的文件」，
  扫出来的那些也一律标成「推测」，与工具亲口写的分得开。
- **思维链只留一行**：推理在流的时候看得见；这一轮思考一结束（开始动手 / 动笔 / 拆解）正文立刻折叠，
  那一行改写成**这段思考落到了什么动作**——「决定调用工具 fetch_json」「将任务拆解为 2 步，先做：…」
  「执行第 2/3 步：改代码」。这句话由事件生成、不经过模型，所以永远与真实发生的事一致，
  也不会因为模型不吐推理而整行消失；同一轮只有一行，跟着事情推进就地改写。
- **「动手的活」不许变成「写一段说明」**：任务定性先认「改动物件 + 改动动作」（要改哪个界面 / 组件 /
  文件），再才是信号词——所以「把思维链隐藏、结果总结成一句话」不会被一个"总结"字判成写作、派给
  写作维度的模型；调度模型自己给的定性也要过这条规则复核。收尾核查同样管「自己招了」：改动类的活
  在本轮**零文件改动**的情况下写「下一步我将…」「我无法修改…」时，先给一轮机会让它现在就做，
  复查仍如此就在答复末尾如实标注「这一步没有交付」。
- **三层验证闸门（任务级 + 汇总级）**：写类工具落盘**当场复核**（Aider `--auto-test` 式）——
  任务书声明的验证命令立刻亲跑，输出不符期望当场回灌，不等收尾；**每个任务一收尾，
  系统就按它自己的任务书亲自核验一次**（调度器被明确要求把交付物与验证命令原样写进
  对应任务的 goal）——失败当场拦截，真实输出回灌给同一 agent 继续做，初次执行加至多
  2 次修正 = 至多三次执行（Claude Code Stop hook 同款，CrewAI max_retry_limit 同语义）；
  全部任务汇总后，系统再按总任务书把守汇总答复。`exit=0` 但输出不含任务书期望值
  （「确认输出 24」跑出 10）**也算失败**——只看退出码等于没验。交付文件另有三类核查
  （不存在 / 本轮没更新 / 幽灵声明），命中先给一轮修正，复查不过就在答复末尾附上程序写的
  权威报告。判定材料（任务集）在沙盒外，模型摸不到。复制 / 备份类任务的任务书由 harness
  自动补一条逐字节比对声明（`python -c` 内联命令闸门照跑）——文本往返丢换行这种肉眼
  不可见的差异，模型干活时就会被拦（第四轮评测 f4 教训）。
- **长期记忆（只放偏好）**：记忆里只留用户的倾向 / 风格 / 习惯（「回复先给结论」「产出文档一律简体中文」）——
  环境事实（路径 / 端口 / 版本）工具能现查、项目约定（工作方式 / 流程规则）由程序与断言保证，
  两类都**不进**记忆（见下面《设计原则》一节）。
  任务收尾自动沉淀（规则抽取 + 本地模型提炼，带同义去重）；侧栏「记忆管理」可查看、补充、删除。
- **防反复迭代**：只读工具重复调用直接回放上次结果；轮次预算（30 轮软提醒收敛 / 60 轮撤工具强制交卷）；
  `task_notes` 任务草稿纸跨上下文压缩持久注入——早期的关键发现不会因压缩「失忆」；
  保鲜参数（最近 8 条工具结果保留原文，压缩摘要放宽到 280 字）。
  实测一个原来 68 次工具调用 / 28 分钟才动笔的简单任务，收敛到 1 次调用 / 18 秒完成。
- **影响路径分析**：改代码前用 `impact_of` 做零依赖静态扫描，列出符号的定义处与引用处，
  先看清波及范围再动手——只改定义、漏掉引用方是回归最常见的来源。
- **协作式停止**：每轮推理与每次工具调用前检查停止标志，随时可中断长任务。
- **Skill 与工具热加载**：Agent Skills 开放标准，命中描述即自动注入；Agent 可自行编写并安装新工具/Skill。
- **每模型上下文计量**：任务顶栏按参与任务的 LLM 各显示一个占用圈——实测 prompt_tokens
  除以该模型自己的窗口，悬停说明是哪个模型；压缩后各圈同步缩小。
- **上下文节流**：工具 schema 按需下发（核心 + 关键词命中，其余只列名字，`find_tools` 现取用法）；
  命中即**整族**下发——检索族 `web_search` / `github_search` / `fetch_url` / `fetch_json` / `browser_snapshot` 成套同来，
  族成员不受数量上限截断（只给 `web_search`、把抓一手来源的工具截掉，等于让「一手来源优先」没有工具可用）。
  Skill 自动注入只给开头几节；多步接力只传「计划 + 各步摘要 + 产出文件」。37 个工具全量下发约
  4.9K tokens/轮，按需下发后常规轮次降到 1.5K 上下，多步任务第 N 步不再背负前 N−1 步的工具输出。
- **权限**：默认权限（写文件与执行命令需确认，越出工作区的路径会被拦截）与完全访问权限
  （直接执行，工作区之外的文件夹也允许读写）可按任务切换，偏好持久化；黑名单命令两种模式都拦。
  想常驻放开路径边界，也可在 config.yaml 的 `[workspace]` 里设 `allow_outside: true`。
- **检索有据（一手来源优先）**：外部事实按**来源等级**处理——`web_search` 只用来找入口（摘要算
  「转述」，不可引用），数字 / 版本 / 日期 / 时效性必须来自 `fetch_url` / `fetch_json` / `github_search`
  抓的 **一手来源**（官方站点、官方 API）。工具输出头直接标注来源性质；只用过搜索、没抓过一手来源
  却在总结里写了数字时，系统在答复末尾追加「转述 · 未经核实」声明并逐条列出。
  实测改进前把摘要的「star 1w+」当结论（GitHub API 实际 17 万），改进后同一任务直接
  `fetch_json` 打官方接口，一次调用拿到真实数字。
- **按名字找仓库找得准**：`github_search` 一次调用打 GitHub 官方搜索接口，按 star 排序返回候选
  （全名 / star / fork / 语言 / 许可证 / 最近更新 / 简介 / 地址）。搜索摘要给不出「有哪些同名项目」，
  只给得出先被索引到的那一个——实测模型据此把一个 80 star 的中文镜像站当成了正主。所以
  `web_search` 侧也兜一枪：`repo_keyword` 判定「在找某个仓库」就自动查一次官方接口，把权威候选
  **排在最前**，并点明「哪个是正主以这份为准，别拿搜索摘要判断」。
- **内置工具**：文件读写、命令执行、联网检索与抓取（搜索 / 按名字搜 GitHub 仓库 / 网页 / JSON 接口 / 截图）、
  SSH 远程运维、git、记忆、小说写作、自我扩展等。

## 核心设计：任务的划分实打实决定执行节奏

这一节是调度层的根基，后期会反复调整，单独立节。

一句话里如果只有**一个任务**，它的小步骤必须**串行**——这是一件事情，前面的步骤会影响
后续步骤，后续步骤必须等前面步骤的结果。一句话里如果有**两个任务**，它们的小步骤可以
**并行**——这是两件互不影响的事情，A 任务的步骤不会影响 B 任务的步骤；处理任务 A 时
如果有空闲算力，可以推进任务 B。

所以**任务的划分不是措辞问题，而是实打实影响处理逻辑、进而影响「一句话」的完成速度**：

- **多个并行任务**：算力全开，算得快。花费的总时间 ≈ 算得最慢的那个任务的时间。
- **多个串行任务**：速度慢。花费的总时间 = 所有任务时间的总和。

这正是第 42 步把调度拆解改成「按能力类型分层的小步骤」的原因：同一个任务内，检索→分析
→写报告这类有先后依赖的步骤只能串行接力（这正是 A→B→C 模型接力的价值）；而「分析仓库」
和「写周报」这种互不影响的任务拆开后就能并行跑，总时间从「各步之和」压到「最慢一步」。
反过来，把本来独立的事错误地捆成一个任务，会把本可并行的时间线强行串成一条——这就是
调度器提示词里「宁可多拆也不错配」的根据。

## 安装

需要 Python 3.10+ 与本机运行中的 [Ollama](https://ollama.com/)（默认 `http://localhost:11434`）。

```bash
python -m venv .venv
# Windows
.venv\Scripts\pip install -r requirements.txt
# Linux / macOS
.venv/bin/pip install -r requirements.txt
```

本地模型用 Ollama 自己拉，配置里默认引用的是这两个（可以随意换）：

```bash
ollama pull gemma4:12b      # 主力：256K 上下文，原生工具调用
ollama pull qwen3.5:4b      # 轻量：速度快，长上下文
```

拉完**不需要手改配置**：AgentForge 发现新模型时会自动探测它的原生上下文长度并写好参数，
在设置页勾选即可用。想指定窗口大小再手写进 `config.yaml` 的 `models` 段（显式配置优先）。

## 换台电脑

```bash
git clone git@github.com:qwertyfew/Agent-Forge.git
cd Agent-Forge

# Windows：双击 start.bat（起点就这一个，不用挑）
# Linux / macOS：
./scripts/start.sh
```

这一个入口会把三件事一次做完，而且**可重复执行、没有副作用**：

1. 缺虚拟环境就自动建 `.venv` 并装依赖；
2. 登记开机自启（下次登录自动把服务拉起来）；
3. 把常驻服务放到后台无窗口跑 —— 页面从此随时打得开。

Windows 上双击后你会看到一段说明文字然后窗口自动关闭：**这是正常的**，服务已经在后台了，
不必留着那个窗口。要停：**双击挨着它的 `stop.bat`**，或者终端里跑 `start.bat --stop`。

`config.yaml` 里不含任何绝对路径，但**在线模型的 API Key 不在版本库里**（见下文「配置」），
所以 clone 下来只需做一次「复制模板 + 填 Key」，就能直接用在线模型开工，
不必先装 Ollama、也不必先拉本地模型：

```bash
cp models.example.json models.json   # 再把里面的 api_key 填成自己的
```

- **在线模型：开箱可用。** 本机一个本地模型都没有时，任务池会自动退回到所有配好的在线模型，
  路由按各维度得分分配；界面上会提示一句「勾选的模型在这台机器上都跑不起来…本次已改用可用模型：X」。
- **本地模型（可选，免费且不出网）**：`ollama pull` 之后自动配置窗口，在设置页勾选即可用。
  勾选过的模型若本机没装，会从任务池里排除（不会让任务撞上 model not found）。

想管别的工作区、或按显存调模型窗口，再照 `config.yaml` 复制一份 `config.lanrun.yaml` 来改；
也可以启动时临时用 `-w <目录>` 覆盖工作区。

## 运行

```bash
# 交互式命令行
python run.py

# 单任务
python run.py -t "在工作区里新建 hello.py 并运行它"

# Web 界面（默认 http://127.0.0.1:8787）
python run.py --web
python run.py -c config.lanrun.yaml --web --port 8787   # 用本机专属配置（若已创建）
```

Windows 下双击 `start.bat` 即可：它把常驻服务放到后台无窗口跑，Web 日志写入 `.run/web.log`。

### 入口只有一个：`start.bat`（Windows）/ `scripts/start.sh`（Linux、macOS）

以前根目录堆着 `start-web`、`start-service`、`install-autostart` 各一对 `.bat`/`.sh`，
Windows 又默认隐藏扩展名，于是看着像四个重名文件，每次都要猜该点哪个。现在**只剩一个入口**，
外加一个专门用来「停」的同伴，两个文件在根目录里挨着：

| 入口 | 作用 |
|---|---|
| `start.bat`（Windows，双击） | 建虚拟环境 + 装依赖 → 登记开机自启 → 起常驻服务 |
| `stop.bat`（Windows，双击） | 停。**不含自己的逻辑**，只转发给 `start.bat --stop` |
| `scripts/start.sh`（Linux、macOS） | 同上（Unix 侧脚本放在 `scripts/`，免得在 Windows 里跟 `.bat` 撞名） |

`stop.bat` 之所以单独存在，只是因为 **Windows 没法「带参数双击」**：`start.bat --stop`
不是一个文件，它是一个文件加一个参数，想用它就得开个终端把参数敲出来——正是这一点不方便。
停的逻辑仍然只有一处（`service.py --stop`），所以这个转发文件不可能跟 `start.bat` 跑偏。

参数（日常不需要，都是从终端里用）：

```bash
start.bat --status              # 现在什么状态（服务在不在、Ollama 通不通）
start.bat --stop                # 停掉常驻服务与 Web 服务
start.bat --no-autostart        # 这次不碰开机自启条目
start.bat --remove-autostart    # 卸载开机自启

./scripts/start.sh --status     # Linux / macOS 同一套参数
```

`--status` 打印的就是「三件事在不在」——常驻服务、Web 端口、Ollama，外加一句本机模型数（真实输出）：

```
常驻服务: 运行中 (PID 16284)
配置文件: config.lanrun.yaml
Web 服务: 正常 http://127.0.0.1:8787
Ollama: 已连接 (http://localhost:11434)
本地模型: 3 个
```

`--remove-autostart` 只删「启动」文件夹里那份 `AgentForge Web UI.bat`——也就是开机自启的启动器本身，
**不碰正在跑的服务**（它会顺手提示「运行中的服务未受影响，要停用 `--stop`」）；没装过就直说没装。

`stop.bat` 就是 `start.bat --stop`。`--status` 与 `--remove-autostart` 现在没有对应的双击文件，
真要的话照 `stop.bat` 复制一份、改掉那个参数即可（三行就能写完）。

`service.py` 是常驻服务本体，也可以直接命令行调：

```bash
# Windows
.venv\Scripts\python.exe service.py --status    # 现在什么状态
.venv\Scripts\python.exe service.py --stop      # 停掉常驻服务与 Web 服务

# Linux / macOS
.venv/bin/python service.py --status
.venv/bin/python service.py --stop
```

### 它怎么「一直开着」

`start.bat` 起的是常驻服务：`service.py` 在后台当保姆，端口没人服务就补位拉起 Web 服务。
它退出（异常、误关窗口、升级重启）也会被拉回来——所以页面随时都打得开。

- **只补位，不抢占**：端口上已经有人（比如你手动开过一次 `run.py --web`）就什么都不做；
  **绝不杀进程**——杀掉可能正在跑的任务，代价远大于等它自己好；
- 发现 8787 没人服务就立刻拉起来，连续失败按指数退避，日志在 `.run/service.log`；
- 每约 1 分钟顺带复查一次 Ollama（见下节），掉了同样拉回来；
- **页面打不开时先跑 `start.bat --status`**。若本机设了 `http_proxy` / `HTTP_PROXY` 环境变量，
  对 `http://127.0.0.1:8787` 的请求会被代理接走、返回 502，看着像服务挂了——其实服务是好的，
  验证本机服务要绕过代理（Python 里用 `urllib.request.build_opener(ProxyHandler({}))`）。

#### 为什么不占任务栏

服务进程用 `pythonw` 起，它拉起 Web 服务时给的创建标志是 **`CREATE_NO_WINDOW`**：

- Web 服务自己拿到的是一个「看不见的控制台」，所以**没有窗口可关、任务栏里没有它**；
- 它再去跑任务命令（`run_command`）时，子进程会**继承这个隐藏控制台**，所以也不会弹一串黑框。
  实测：父进程用 `CREATE_NO_WINDOW` 时，子进程 `GetConsoleWindow()` 返回 0（不弹窗）；
  而父进程用 `pythonw` 时子进程反而会拿到一个**可见**窗口——所以这里不能图省事换成 `pythonw`。
- 曾经的 bug 就是用了 `DETACHED_PROCESS`：它给控制台程序**新开一个可见窗口**，
  一关掉服务就死、保姆又拉起来，于是「关了又弹、关了又弹」。

任务里要打开的**新**命令行/程序不受影响，照旧正常出现在任务栏——隐藏的只有 AgentForge 自己这两个进程。

#### 点一下工作区路径，窗口直接到前台

侧栏底部那行工作区路径、以及回复末尾的产出文件卡片，点一下就会用系统默认程序打开。
Windows 上这里有第二道坑：`os.startfile` 打开的窗口**不会跑到前台**——前台锁不许后台进程抢焦点，
于是表现成「点了一次好像没反应，得再点一次任务栏上的文件资源管理器」。所以打开之后还会补一步：
在可见顶层窗口里找到目标对应的那个，借前台线程的资格把它抬上来（`agentforge/reveal.py`）。
找不到就什么都不做，行为与以前一样；只有用户点击触发的接口会这么做，后台跑任务时不会突然抢你的焦点。

### 开机自启

`start.bat` 第一次跑就会顺手登记好，之后每次登录自动把常驻服务拉起来，不需要你再操作。
启动项里必须写**本机的绝对路径**，所以它不能进仓库，只能由入口脚本现场生成：

- **Windows**：写进用户「启动」文件夹的 `AgentForge Web UI.bat`。它只负责把常驻服务拉起来
  （`cd` 到项目目录后 `start "" ".venv\Scripts\pythonw.exe" service.py`）——**服务本身无窗口**，
  任务栏里不会多出东西，也没有窗口可以误关。唯一代价是登录瞬间会闪过一个**极短的 cmd 窗口**，
  那是 Windows 执行这个 `.bat` 启动器本身留下的；要做成完全零闪得建 `.lnk` 快捷方式，而创建
  快捷方式所需的 COM 在部分安全策略收紧的机器上会被拦下，所以这里选了更稳的 `.bat`。
  它不需管理员、不写注册表；任务计划的 `schtasks.exe` 在某些安全策略下同样会被禁用，用启动文件夹更省事。
  生成的文件是**纯 ASCII + CRLF**（`echo` 写出的编码与 cmd 当前代码页一致，即使项目路径含中文也不会错位）。
  不要了就跑 `start.bat --remove-autostart`（只删它自己写的那份启动项，不动正在跑的服务）。
- **Linux**：写 XDG autostart 条目 `~/.config/autostart/agentforge.desktop`。
- **macOS**：不读 XDG autostart，入口脚本会直说并让你改用 launchd（或每次手动跑 `./scripts/start.sh`）。
- 在 Windows 的 Git Bash / MSYS 里跑 `.sh` 会被直接拦下——那里 `pwd` 返回 `/d/...` 这类 MSYS
  路径，写进启动项在真实登录流程里解析不了；脚本会提示改用对应的 `.bat`。

## 本地模型的上游：Ollama 自动拉起

本地模型全部依赖本机 Ollama。长期不关机的机器上，它可能被手动退出、升级时重启或崩掉——
这时项目里所有本地模型会**静默失效**，界面上只有一句「Ollama 无响应」。所以加了一层守卫
（`agentforge/ollamaguard.py`），三条路径复用同一份实现：

- **Web 启动时**（`serve()`）：先把 Ollama 确保起来，再去打印状态；
- **界面上**：左下角状态点每 30 秒体检一次，发现没响应就自动拉起（`POST /api/ollama/ensure`，
  带冷却，不会把进程刷爆），拉起来了会弹一条提示；**没响应时点它 = 立即重试拉起**（有响应时才跳服务页）；
- **常驻服务**（`service.py`）：每约 1 分钟复查一次。

拉起策略：优先 **Ollama 桌面版**（`ollama app.exe`，就是用户平时开机自启那一份，单实例不会抢端口），
找不到才退回 `ollama serve`。判定成功以「`/api/tags` 真能应答」为准，不是「进程生出来了」就算数。
拉起时用 `CREATE_NO_WINDOW`，所以退回 `ollama serve` 那条路也不会在任务栏留一个黑框。
日志在 `.run/ollama.log`。

```yaml
ollama:
  host: http://localhost:11434
  auto_start: true        # 关掉就只提示、不动作
  auto_start_wait: 45     # 拉起后最多等这么多秒
```

只想自己掌控时把 `auto_start` 设成 `false`，界面不会做任何动作。

## 配置

`config.yaml` 是**通用模板**，跟着仓库走，刻意不含任何绝对路径——换台电脑 clone 下来直接能用。

想按本机情况调整（工作区路径、模型窗口、步数上限…），**照它复制一份 `config.lanrun.yaml` 来改**：

```bash
cp config.yaml config.lanrun.yaml
```

`config.lanrun.yaml` 已 gitignore，属于你那台机器，不会污染版本库。启动脚本会优先用它，
没有就退回 `config.yaml`。也可以随时用 `-c` 指定别的配置文件。

```yaml
ollama:
  host: http://localhost:11434
models:
  gemma:            # 模型 key，任务分配时按 key 引用
    name: gemma4:12b
    num_ctx: 32768
    think: true     # 必须为 true，否则推理过程会混进正文
workspace:
  # 不写 root = 用本仓库所在目录，换机器免改
  root: D:\path\to\your\workspace   # 想管别的工作区时才写，越界读写一律拒绝
  # state_dir: D:\where\to\keep\.agentforge   # 长期记忆与附件的落点，默认 <工作区>/.agentforge
```

版本库里**不含** `models.json`：里面存着在线模型的 API Key，入库等于把密钥写进 git 历史
（一旦提交就只能靠重写历史清除），所以它已 gitignore。仓库里放的是**模板**
`models.example.json`——结构与 `models.json` 完全一致，只是 `api_key` 全部留空：

```bash
cp models.example.json models.json   # 填上 api_key 即可用
```

`api_key` 为空串的模型会被标成「本机不可用」，自动退出路由与任务池，
所以模板里没填的那几家不会把任务带沟里，只会被跳过。

**不含**下列机器相关状态（已 gitignore）：`models.json`（在线模型配置与 API Key）、
`config.lanrun.yaml` / `config.local.yaml`
（本机专属配置，含绝对路径与按显存调的模型窗口）、`models.local.json`（本地模型的自动探测结果，
每台机器装了哪些模型、显存多大都不同）、`.tasks.json`、`.prefs.json`、`.sessions/`、`.venv/`、`.run/`。
`.agentforge/` 里的运行期产物（任务笔记、上传附件）不入库，但
**长期记忆 `.agentforge/memory.md` 是例外**——只有几百字节且跨机器通用，随仓库同步。

### 跨平台脚本的行尾与编码

所有 `.bat` 与 `.sh` 都受这两条硬约束，由 `.gitattributes` 强制住，改脚本时别踩：

- **`.bat` 必须「纯 ASCII + CRLF」**。cmd.exe 按 CRLF 计算字节偏移，纯 LF 会让它逐行错位、
  从行中间开始执行（把半句话当命令跑）；在 936（GBK）控制台下，UTF-8 中文的尾字节还会被
  GBK 解码器**连同行尾 CR 一起吃掉**，照样错位。存成 GBK 能让 cmd 跑通，但编辑器（默认 UTF-8）
  打开就是满屏乱码——所以这些文件**只用英文注释与提示**。`*.bat text eol=crlf` 守住这条。
- **`.sh` 必须 LF**。CRLF 会让 shebang 变成 `#!/usr/bin/env bash^M`，Linux / macOS 上直接执行
  会报 `bad interpreter`。`*.sh text eol=lf` 守住这条。
- **脚本里调外部命令别用裸名字**。`stop.bat` 判「是不是双击」用到了 `find.exe`，写成裸 `find`
  时一脚踩空：cmd 从 Git Bash 继承的 PATH 里，Git 的 `usr\bin` 排在 System32 前面，
  于是 `find` 落到了 **GNU find** 上（实测报 `find: '/i': No such file or directory`，
  而且错误被吞在管道里）。结果是**双击能跑、从 Git Bash 起就哑**——同一个文件两种命运，
  最难查的一类。改成 `"%SystemRoot%\System32\find.exe"` 就与 PATH 无关了。
  同一类的还有 `sort`、`more`、`where`、`timeout`、`attrib`——Git for Windows 里都有同名件。

## 回归：改完必须自证

判据只有一条：**把这条从代码里删掉，测试会不会红？** 红 → 才算架构保证；不红 → 它只是「劝」，得说明为什么允许它留在那一层。

常驻回归 **34 个文件（25 Python + 9 前端）**，Python 侧 824 项断言逐条打印
（重跑即复现；前端 9 个 `.mjs` 共 225 项）。跑法、依赖（Python 要用项目 `.venv`，
前端 `.mjs` 需要 `jsdom`）以及「**SKIP 不等于通过**」这个坑，见
[`docs/contracts.md`](docs/contracts.md) 第四节。

断言之外还有一把更粗的尺子：**评测集**（`evals/tasks.yaml`，20 条跨五类任务，
判定零模型调用）+ A/B 对比——改模型、改配置、删功能前后各跑一轮，用数据说话。
见 [`docs/benchmark.md`](docs/benchmark.md)。

## 设计原则：设定靠架构，偏好靠记忆

第 19 步是一条原则被发现的经过。这一节把它单独拎出来讲清楚，因为它是之后每一个改动的尺子——
动手修一个 bug 之前，先用它回答一个更前置的问题：**这件事该由谁定？**

### 一、不需要模型判断的事，就不要让它经过模型

一个行为该由**程序**定还是由**模型**定，只看一件事：**它的正确答案，跟模型的输出有关系吗？**
没关系，就不该把决定权交给模型——模型每多参与一次，就多一次它出错的机会。

两个真实例子，它们原先恰恰被交给了模型：

| 该发生的事 | 正确答案取决于 | 所以该由谁定 |
|---|---|---|
| 头像与计时：**会话一开始**就该在 | 与模型说什么、说多快**无关** | **程序**：提问落盘那一刻就建（`addUser()` → `beginReply()`），基准取那一刻 |
| 复制 / 重新生成 / 朗读按钮：**整段回复结束**才该有 | 与模型中途吐了几段、说了什么**无关** | **程序**：全流程走完由唯一出口生成（`settleReply()`），中途一律不出现 |

原先的错误做法，是把这个"确定时刻"**挂到某个模型行为上**：头像行 lazy 挂在"第一个 AI 元素"，
于是"头像什么时候出现"实际交给了"模型什么时候吐第一个 token"——首轮跑得慢、只吐胶囊、
甚至一个字都不吐，它就迟到或缺席；按钮挂在 `history` 事件上，于是在回答还没完时就冒出来。
**把"必然要发生"的事，系在"不一定发生"的事件上，它就会跟着那个事件一起缺席。**

问自己三个问题，用来决定一件事该用什么方式修（第 19 步的三问，这里当尺子用）：

1. 这件事的**正确答案**依赖模型判断吗？——依赖，才留在模型侧；不依赖，**由程序定**。
2. 程序能不能**在出错的那一刻**发现它？——能，就加程序侧核查（闸门 / 唯一出口 / 兜底）。
3. 三个月后还会不会重犯？——会，就写成 `tools/test_*.py` 常驻断言，让它"改回去立刻红"。

### 二、记忆放「偏好」，不放「设定」

这条原则有一个同样硬的反面：**不能指望"把一条记忆写进提示词"来解决"必须发生"的事。**

| | 偏好（可以进记忆） | 设定（必须靠架构） |
|---|---|---|
| 是什么 | 倾向、风格、习惯 | 必须发生的行为 |
| 例子 | "回答尽量简洁"、"优先用本地模型"、"先给结论" | "有头像和计时"、"回复结尾必须有工具条"、"失败必须给出下一步" |
| 载体 | `.agentforge/memory.md`、技能文本 | 代码（程序强制）+ 常驻断言 |
| 偶尔不生效 | **可以接受**——它本来就是个"尽量" | **不可接受**——用户看到的就是 bug |

一句话：**记忆是概率，架构是保证。** 把设定放进记忆、再靠一段提示词"请模型遵守"，
等于把保证降级成概率——模型没读到、或读到了没照做，这件事就不发生。
第 18 步已经吃过一次亏：`self-verification` 技能明明**加载了**，编造的目录清单照发不误。
**「写下来了」不等于「会生效」。**

所以规矩是两句话：

> **记忆里只放"偏好"——允许偶尔不生效的东西。**
> **凡是"偶尔不生效就会变成 bug"的，一律不许待在记忆里，必须有硬性架构保证。**

第 20 步就是拿这把尺子去清**记忆自己**：原先记忆分 L1 事实 / L2 约定 / L3 偏好三层，
可事实有工具能现查、约定只有架构才管得住——真正该留在记忆里的只剩偏好那一层。
于是三层收成一层，存量那批「项目约定」条目一次性删掉；`memory.py` 里的分层、
`autonote` 的层标签、`remember` 的 `layer` 参数与侧栏的分层统计一并拿掉。

### 三、落地：把一条内容对号入座

改任何东西之前先分类：**这条是"偏好"还是"设定"？**

- **偏好** → 写进记忆 / 技能，允许它偶尔不按偏好来（代价轻微）。
- **设定** → 写进代码，并且用常驻断言钉死。判据是：**"写下来"不算数，"删掉它测试会红"才算数。**

这把尺子也是给问题分档的标准——哪条是 **A 程序强制**、哪条只是 **C 提示词劝**、
哪些**有意**留在"劝"这一层以及为什么，见下一节。

### 四、脚手架只减不增

mini-swe-agent 用约 100 行、唯一工具 bash 在 SWE-bench Verified 拿到 >74%——
在强模型上。它的存在不是让我们拆掉验证闸门（本地小模型下，重闸门有存在理由），
而是一面镜子：**harness 的每个功能都必须用评测证明自己**。

> 每想加一个功能，先问：「mini-swe-agent 会需要这个吗？加了它，
> 评测集里哪条任务会从红变绿？」——答不出具体任务和数字的，不加；
> 已加而答不出的，列入待删清单。删功能前同样先跑一轮 bench：删完 20 条全绿才真删。

评测的跑法与判读见 [`docs/benchmark.md`](docs/benchmark.md)。

## 修复清单与能力的契约

哪些是**硬约束**（程序强制 + 常驻断言）、哪些只是**叮嘱**（有意留在提示词/纪律那一层），以及各项能力的可观测契约、脚本寿命约定、结论的来源等级——全文在 [`docs/contracts.md`](docs/contracts.md)。
判据只有一条：**把这条从代码里删掉，测试会不会红？** 红 → 才算架构保证。

## 本地模型性能基准

新增/更换本地模型后，想知道它在这台机器上到底跑多快，用 `tools/bench.py`：

```
python tools/bench.py                # 测所有已装模型
python tools/bench.py gpt-oss:20b    # 只测一个
python tools/bench.py --cold --tools # 冷加载 + 工具调用冒烟
```

它读的是 Ollama 自己的计时字段（不是掐秒表），所以横向可比：**加载s** 是模型进显存的耗时，
**提示tok/s** 是预填充速度（决定首字等多久），**生成tok/s** 是解码速度（决定读起来快不快），
末尾还会带上 `ollama ps` 的显存/算力分布，用来判断有没有被挤到 CPU 上。
