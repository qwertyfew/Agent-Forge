# AgentForge

本机运行的 AI Agent Harness：用 Ollama 上的本地模型（可选接入付费 API）执行真实任务——
读写文件、跑命令、联网检索、SSH 远程运维、写长篇小说，甚至给自己写新工具和 Skill。

前端是零依赖的单文件页面（`web/index.html`），后端是纯标准库的 HTTP 服务（`webui.py`），
没有重框架、没有构建步骤，`git clone` 后装三个依赖就能跑。

## 特性

- **多模型与自动分配**：为每个模型打八维度能力分，任务按维度贪心挑选最优组合（可限定只用本地模型）。
- **多 Agent 调度**：一个本地「决策模型」把请求拆成语义独立的任务，指派给最合适的执行 agent、
  维护共享进度接力交接；独立任务可并行波次执行（本地模型串行闸门防显存互挤，同文件写入串行保护）。
  决策模型只做拆解/指派/交接和几句简单对话，重活一律派给最强执行模型；拆解失败自动回退规则编排。
- **本地优先**：默认全部走 Ollama 本地模型，零 API 费用；付费模型（DeepSeek / SiliconFlow）按需勾选启用。
  Ollama 挂了会自动拉起（桌面版优先，退回 `ollama serve`），判定标准是「真能应答」而非「进程生出来了」。
- **Web 服务常驻**：双击一次 `start.bat`（Windows）/ 跑一次 `./scripts/start.sh`（Linux、macOS）就够了——
  它建好虚拟环境、登记开机自启，再起一个**无窗口**的保姆进程：端口没人服务就补位拉起，
  只补位不抢占、不杀进程（跑着任务时重启的代价远大于等它自己好）。
  服务本身不占任务栏、没有窗口可以误关，开机自启也随之装好——换台机器 clone 完即可复现。
- **任务台账**：每个任务记录状态、耗时、token 与预估费用、产出文件、对话历史，重启后自动把遗留的
  「执行中」标记为已中断。
- **产出追踪**：写文件工具精确记录 + 任务前后工作区快照对比，任务产出了哪些文件一目了然。
- **长期记忆（分层）**：每条记忆按语义粒度打层标签——L1 原子事实（路径/端口/版本）、
  L2 项目约定、L3 用户偏好；注入时按任务类型决定检索深度（技术活优先 L1，闲聊优先 L3/L2）。
  任务收尾自动沉淀（规则抽取 + 本地模型提炼，带同义去重）；侧栏「记忆管理」可查看、补充、删除。
- **防反复迭代**：只读工具重复调用直接回放上次结果；轮次预算（30 轮软提醒收敛 / 60 轮撤工具强制交卷）；
  `task_notes` 任务草稿纸跨上下文压缩持久注入——早期的关键发现不会因压缩「失忆」；
  保鲜参数（最近 8 条工具结果保留原文，压缩摘要放宽到 280 字）。
  实测一个原来 68 次工具调用 / 28 分钟才动笔的简单任务，收敛到 1 次调用 / 18 秒完成。
- **影响路径分析**：改代码前用 `impact_of` 做零依赖静态扫描，列出符号的定义处与引用处，
  先看清波及范围再动手——只改定义、漏掉引用方是回归最常见的来源。
- **协作式停止**：每轮推理与每次工具调用前检查停止标志，随时可中断长任务。
- **Skill 与工具热加载**：Agent Skills 开放标准，命中描述即自动注入；Agent 可自行编写并安装新工具/Skill。
- **上下文节流**：工具 schema 按需下发（核心 + 关键词命中，其余只列名字，`find_tools` 现取用法）；
  Skill 自动注入只给开头几节；多步接力只传「计划 + 各步摘要 + 产出文件」。35 个工具全量下发约
  4.3K tokens/轮，按需下发后常规轮次约 1.7K，多步任务第 N 步不再背负前 N−1 步的工具输出。
- **权限**：默认权限（写文件与执行命令需确认，越出工作区的路径会被拦截）与完全访问权限
  （直接执行，工作区之外的文件夹也允许读写）可按任务切换，偏好持久化；黑名单命令两种模式都拦。
  想常驻放开路径边界，也可在 config.yaml 的 `[workspace]` 里设 `allow_outside: true`。
- **检索有据（一手来源优先）**：外部事实按**来源等级**处理——`web_search` 只用来找入口（摘要算
  「转述」，不可引用），数字 / 版本 / 日期 / 时效性必须来自 `fetch_url` / `fetch_json` 抓的
  **一手来源**（官方站点、官方 API）。工具输出头直接标注来源性质；只用过搜索、没抓过一手来源
  却在总结里写了数字时，系统在答复末尾追加「转述 · 未经核实」声明并逐条列出。
  实测改进前把摘要的「star 1w+」当结论（GitHub API 实际 17 万），改进后同一任务直接
  `fetch_json` 打官方接口，一次调用拿到真实数字。
- **内置工具**：文件读写、命令执行、联网检索与抓取（搜索 / 网页 / JSON 接口 / 截图）、
  SSH 远程运维、git、记忆、小说写作、自我扩展等。

## 安装

需要 Python 3.10+ 与本机运行中的 [Ollama](https://ollama.com/)（默认 `http://localhost:11434`）。

```bash
python -m venv .venv
# Windows
.venv\Scripts\pip install -r requirements.txt
# Linux / macOS
.venv/bin/pip install -r requirements.txt
```

本地模型用 Ollama 自己拉，配置里默认引用的是这两个（可以随意换）：

```bash
ollama pull gemma4:12b      # 主力：256K 上下文，原生工具调用
ollama pull qwen3.5:4b      # 轻量：速度快，长上下文
```

拉完**不需要手改配置**：AgentForge 发现新模型时会自动探测它的原生上下文长度并写好参数，
在设置页勾选即可用。想指定窗口大小再手写进 `config.yaml` 的 `models` 段（显式配置优先）。

## 换台电脑

```bash
git clone git@github.com:qwertyfew/Agent-Forge.git
cd Agent-Forge

# Windows：双击 start.bat（就这一个文件，不用挑）
# Linux / macOS：
./scripts/start.sh
```

这一个入口会把三件事一次做完，而且**可重复执行、没有副作用**：

1. 缺虚拟环境就自动建 `.venv` 并装依赖；
2. 登记开机自启（下次登录自动把服务拉起来）；
3. 把常驻服务放到后台无窗口跑 —— 页面从此随时打得开。

Windows 上双击后你会看到一段说明文字然后窗口自动关闭：**这是正常的**，服务已经在后台了，
不必留着那个窗口。要停：终端里跑 `start.bat --stop`。

`config.yaml` 里不含任何绝对路径，但**在线模型的 API Key 不在版本库里**（见下文「配置」），
所以 clone 下来只需做一次「复制模板 + 填 Key」，就能直接用在线模型开工，
不必先装 Ollama、也不必先拉本地模型：

```bash
cp models.example.json models.json   # 再把里面的 api_key 填成自己的
```

- **在线模型：开箱可用。** 本机一个本地模型都没有时，任务池会自动退回到所有配好的在线模型，
  路由按各维度得分分配；界面上会提示一句「勾选的模型在这台机器上都跑不起来…本次已改用可用模型：X」。
- **本地模型（可选，免费且不出网）**：`ollama pull` 之后自动配置窗口，在设置页勾选即可用。
  勾选过的模型若本机没装，会从任务池里排除（不会让任务撞上 model not found）。

想管别的工作区、或按显存调模型窗口，再照 `config.yaml` 复制一份 `config.lanrun.yaml` 来改；
也可以启动时临时用 `-w <目录>` 覆盖工作区。

## 运行

```bash
# 交互式命令行
python run.py

# 单任务
python run.py -t "在工作区里新建 hello.py 并运行它"

# Web 界面（默认 http://127.0.0.1:8787）
python run.py --web
python run.py -c config.lanrun.yaml --web --port 8787   # 用本机专属配置（若已创建）
```

Windows 下双击 `start.bat` 即可：它把常驻服务放到后台无窗口跑，Web 日志写入 `.run/web.log`。

### 启动脚本只有一个：`start.bat`（Windows）/ `scripts/start.sh`（Linux、macOS）

以前根目录堆着 `start-web`、`start-service`、`install-autostart` 各一对 `.bat`/`.sh`，
Windows 又默认隐藏扩展名，于是看着像四个重名文件，每次都要猜该点哪个。现在**只剩一个入口**：

| 入口 | 作用 |
|---|---|
| `start.bat`（Windows，双击） | 建虚拟环境 + 装依赖 → 登记开机自启 → 起常驻服务 |
| `scripts/start.sh`（Linux、macOS） | 同上（Unix 侧脚本放在 `scripts/`，免得在 Windows 里跟 `.bat` 撞名） |

参数（日常不需要，都是从终端里用）：

```bash
start.bat --status              # 现在什么状态（服务在不在、Ollama 通不通）
start.bat --stop                # 停掉常驻服务与 Web 服务
start.bat --no-autostart        # 这次不碰开机自启条目
start.bat --remove-autostart    # 卸载开机自启

./scripts/start.sh --status     # Linux / macOS 同一套参数
```

`service.py` 是常驻服务本体，也可以直接命令行调：

```bash
# Windows
.venv\Scripts\python.exe service.py --status    # 现在什么状态
.venv\Scripts\python.exe service.py --stop      # 停掉常驻服务与 Web 服务

# Linux / macOS
.venv/bin/python service.py --status
.venv/bin/python service.py --stop
```

### 它怎么「一直开着」

`start.bat` 起的是常驻服务：`service.py` 在后台当保姆，端口没人服务就补位拉起 Web 服务。
它退出（异常、误关窗口、升级重启）也会被拉回来——所以页面随时都打得开。

- **只补位，不抢占**：端口上已经有人（比如你手动开过一次 `run.py --web`）就什么都不做；
  **绝不杀进程**——杀掉可能正在跑的任务，代价远大于等它自己好；
- 发现 8787 没人服务就立刻拉起来，连续失败按指数退避，日志在 `.run/service.log`；
- 每约 1 分钟顺带复查一次 Ollama（见下节），掉了同样拉回来。

#### 为什么不占任务栏

服务进程用 `pythonw` 起，它拉起 Web 服务时给的创建标志是 **`CREATE_NO_WINDOW`**：

- Web 服务自己拿到的是一个「看不见的控制台」，所以**没有窗口可关、任务栏里没有它**；
- 它再去跑任务命令（`run_command`）时，子进程会**继承这个隐藏控制台**，所以也不会弹一串黑框。
  实测：父进程用 `CREATE_NO_WINDOW` 时，子进程 `GetConsoleWindow()` 返回 0（不弹窗）；
  而父进程用 `pythonw` 时子进程反而会拿到一个**可见**窗口——所以这里不能图省事换成 `pythonw`。
- 曾经的 bug 就是用了 `DETACHED_PROCESS`：它给控制台程序**新开一个可见窗口**，
  一关掉服务就死、保姆又拉起来，于是「关了又弹、关了又弹」。

任务里要打开的**新**命令行/程序不受影响，照旧正常出现在任务栏——隐藏的只有 AgentForge 自己这两个进程。

### 开机自启

`start.bat` 第一次跑就会顺手登记好，之后每次登录自动把常驻服务拉起来，不需要你再操作。
启动项里必须写**本机的绝对路径**，所以它不能进仓库，只能由入口脚本现场生成：

- **Windows**：写进用户「启动」文件夹的 `AgentForge Web UI.bat`。它只负责把常驻服务拉起来
  （`cd` 到项目目录后 `start "" ".venv\Scripts\pythonw.exe" service.py`）——**服务本身无窗口**，
  任务栏里不会多出东西，也没有窗口可以误关。唯一代价是登录瞬间会闪过一个**极短的 cmd 窗口**，
  那是 Windows 执行这个 `.bat` 启动器本身留下的；要做成完全零闪得建 `.lnk` 快捷方式，而创建
  快捷方式所需的 COM 在部分安全策略收紧的机器上会被拦下，所以这里选了更稳的 `.bat`。
  它不需管理员、不写注册表；任务计划的 `schtasks.exe` 在某些安全策略下同样会被禁用，用启动文件夹更省事。
  生成的文件是**纯 ASCII + CRLF**（`echo` 写出的编码与 cmd 当前代码页一致，即使项目路径含中文也不会错位）。
  不要了就跑 `start.bat --remove-autostart`（只删它自己写的那份启动项，不动正在跑的服务）。
- **Linux**：写 XDG autostart 条目 `~/.config/autostart/agentforge.desktop`。
- **macOS**：不读 XDG autostart，入口脚本会直说并让你改用 launchd（或每次手动跑 `./scripts/start.sh`）。
- 在 Windows 的 Git Bash / MSYS 里跑 `.sh` 会被直接拦下——那里 `pwd` 返回 `/d/...` 这类 MSYS
  路径，写进启动项在真实登录流程里解析不了；脚本会提示改用对应的 `.bat`。

## 本地模型的上游：Ollama 自动拉起

本地模型全部依赖本机 Ollama。长期不关机的机器上，它可能被手动退出、升级时重启或崩掉——
这时项目里所有本地模型会**静默失效**，界面上只有一句「Ollama 无响应」。所以加了一层守卫
（`agentforge/ollamaguard.py`），三条路径复用同一份实现：

- **Web 启动时**（`serve()`）：先把 Ollama 确保起来，再去打印状态；
- **界面上**：左下角状态点每 30 秒体检一次，发现没响应就自动拉起（`POST /api/ollama/ensure`，
  带冷却，不会把进程刷爆），拉起来了会弹一条提示；**没响应时点它 = 立即重试拉起**（有响应时才跳服务页）；
- **常驻服务**（`service.py`）：每约 1 分钟复查一次。

拉起策略：优先 **Ollama 桌面版**（`ollama app.exe`，就是用户平时开机自启那一份，单实例不会抢端口），
找不到才退回 `ollama serve`。判定成功以「`/api/tags` 真能应答」为准，不是「进程生出来了」就算数。
拉起时用 `CREATE_NO_WINDOW`，所以退回 `ollama serve` 那条路也不会在任务栏留一个黑框。
日志在 `.run/ollama.log`。

```yaml
ollama:
  host: http://localhost:11434
  auto_start: true        # 关掉就只提示、不动作
  auto_start_wait: 45     # 拉起后最多等这么多秒
```

只想自己掌控时把 `auto_start` 设成 `false`，界面不会做任何动作。

## 配置

`config.yaml` 是**通用模板**，跟着仓库走，刻意不含任何绝对路径——换台电脑 clone 下来直接能用。

想按本机情况调整（工作区路径、模型窗口、步数上限…），**照它复制一份 `config.lanrun.yaml` 来改**：

```bash
cp config.yaml config.lanrun.yaml
```

`config.lanrun.yaml` 已 gitignore，属于你那台机器，不会污染版本库。启动脚本会优先用它，
没有就退回 `config.yaml`。也可以随时用 `-c` 指定别的配置文件。

```yaml
ollama:
  host: http://localhost:11434
models:
  gemma:            # 模型 key，任务分配时按 key 引用
    name: gemma4:12b
    num_ctx: 32768
    think: true     # 必须为 true，否则推理过程会混进正文
workspace:
  # 不写 root = 用本仓库所在目录，换机器免改
  root: D:\path\to\your\workspace   # 想管别的工作区时才写，越界读写一律拒绝
  # state_dir: D:\where\to\keep\.agentforge   # 长期记忆与附件的落点，默认 <工作区>/.agentforge
```

版本库里**不含** `models.json`：里面存着在线模型的 API Key，入库等于把密钥写进 git 历史
（一旦提交就只能靠重写历史清除），所以它已 gitignore。仓库里放的是**模板**
`models.example.json`——结构与 `models.json` 完全一致，只是 `api_key` 全部留空：

```bash
cp models.example.json models.json   # 填上 api_key 即可用
```

`api_key` 为空串的模型会被标成「本机不可用」，自动退出路由与任务池，
所以模板里没填的那几家不会把任务带沟里，只会被跳过。

**不含**下列机器相关状态（已 gitignore）：`models.json`（在线模型配置与 API Key）、
`config.lanrun.yaml` / `config.local.yaml`
（本机专属配置，含绝对路径与按显存调的模型窗口）、`models.local.json`（本地模型的自动探测结果，
每台机器装了哪些模型、显存多大都不同）、`.tasks.json`、`.prefs.json`、`.sessions/`、`.venv/`、`.run/`。
`.agentforge/` 里的运行期产物（任务笔记、上传附件）不入库，但
**长期记忆 `.agentforge/memory.md` 是例外**——只有几百字节且跨机器通用，随仓库同步。

```
web/index.html         全部前端（零依赖单文件）
start.bat              Windows 唯一入口：建环境 + 装自启 + 起常驻服务（双击它就行）
scripts/start.sh       Linux / macOS 同一件事（放在子目录，免得在 Windows 里与 .bat 撞名）
agentforge/
  loop.py              单轮智能体循环（推理 → 工具 → 回灌）
  orchestrator.py      任务编排：拆解、分配、限步、停止
  dispatcher.py        多 agent 调度：决策模型拆解/指派/交接，并行波次
  config.py            配置模型与解析（轮次预算、调度器等）
  providers.py         模型 Provider 抽象（OpenAI 兼容 / Anthropic / Ollama）
  router.py scores.py  维度路由与评分

  ollamaguard.py       本地模型上游守卫：探测 / 定位 / 拉起 Ollama

  verify.py            收尾验证闸门（提取/运行/核查，系统侧强制）
  sources.py           一手来源核查（搜索过却没抓一手来源时，附「转述·未核实」声明）

skills/                内置技能（frontend-design / novel-writing / web-browsing / remote-ops /
                       self-verification / first-party-source / self-extension ...）
tools/                 开发/运维工具（bench.py 模型性能基准、fastpull.py 模型拉取与体检、
                       test_readcache.py / test_verify_gate.py / test_sources_gate.py 常驻回归、
                       test_tool_panel.mjs 前端工具面板回归）
```

### 跨平台脚本的行尾与编码

所有 `.bat` 与 `.sh` 都受这两条硬约束，由 `.gitattributes` 强制住，改脚本时别踩：

- **`.bat` 必须「纯 ASCII + CRLF」**。cmd.exe 按 CRLF 计算字节偏移，纯 LF 会让它逐行错位、
  从行中间开始执行（把半句话当命令跑）；在 936（GBK）控制台下，UTF-8 中文的尾字节还会被
  GBK 解码器**连同行尾 CR 一起吃掉**，照样错位。存成 GBK 能让 cmd 跑通，但编辑器（默认 UTF-8）
  打开就是满屏乱码——所以这些文件**只用英文注释与提示**。`*.bat text eol=crlf` 守住这条。
- **`.sh` 必须 LF**。CRLF 会让 shebang 变成 `#!/usr/bin/env bash^M`，Linux / macOS 上直接执行
  会报 `bad interpreter`。`*.sh text eol=lf` 守住这条。

## 它是怎么一步步训出来的

这个 agent 不是一次写成的——几十个 commit、一轮轮真实任务实测，都是下面这个循环转出来的。
这一节讲**循环本身**：具体某一版的代码会过时，方法是可复用的。

```
先让它能跑 → 拿真实任务测 → 读事件流定位真问题 → 小步修、改完自证 → 把能力沉淀下来
    ↑                                                                    │
    └──────────────────────  下一轮带着沉淀再来  ──────────────────────────┘
```

### 1. 先让它能跑

不追求功能齐全，先打通一条最小闭环：本地 Ollama 优先（零 API 成本）→ 工具调用 → Skill 自动注入
→ 零依赖单文件 Web UI。跑通了才谈得上「观察它怎么出错」——跑不起来的时候，任何设计都是空想。

### 2. 拿真实任务当测试集，从事件流里读事实

真正的提升来自**让它做真活**——整理一本小说的素材、调研一个外部项目、修一个真实的 bug——
然后看它**到底**怎么失败的。关键动作是读它自己的事件流：编排发出的每一个事件
（`route` / `dispatch` / `assign` / `tool_start` / `task_done` …）都进 SSE 总线，
复盘时是**事实**而不是猜测——它有没有被派重活、哪一步空转了、文件到底写没写，看事件流就知道
（这一层可观测性见「能力的契约」第 1 节）。

一个具体例子：同一个简单任务，修复前 **28 分钟 / 68 次工具调用**，修复后 **18 秒 / 1 次调用**
（`t101213344526d9`）。数字来自事件流，不来自感觉。

另一个例子说明**流程绿 ≠ 结论对**：一次外部检索任务，事件流里每一步都正常（路由 → 派活 →
检索 → 收尾，51 秒 / 3 次调用 / 全免费），但把它的产出拿去和 GitHub API 一对，
数字差了整整一个数量级。**事件流只能证明它照流程走完了，不能证明它做对了**——
后者得靠一手来源去核，这就是第 15 步的由来。

### 3. 小步修，改完必须自证

定位到问题后**一轮改一处**：一轮改动一个 commit，改完必须给出真实命令 + 真实输出，
不接受「我觉得修好了」。（这条纪律本身也沉淀成了 `small-steps-iteration` 技能。）

它的价值在第八轮暴露得最彻底：一次修复任务的 3 次 `edit_file` 其实**全部失败**，
agent 没读错误、也没重跑测试，就在总结里谎报「所有断言通过」——**轮次收敛了，但结论是编的**。
于是有了第 12 步的三层防线：验证命令由**系统亲自跑**，模型**只有解读权、没有裁定权**。

### 4. 每轮结束，把「能力」沉淀下来

这是循环里最关键的一步，也是这个项目真正在攒的东西。跑完一轮，除了修代码，还要把这一轮学到的
**留下来**，分四类落点：

| 落点 | 放什么 | 落在哪 | 机制 |
|---|---|---|---|
| **记忆** | 用户偏好、项目约定、可执行的事实 | `.agentforge/memory.md` | `memory.py` 分层（L1 事实 / L2 约定 / L3 偏好）+ `autonote.py` 收尾自动抽取 |
| **技能** | 「这类任务该怎么做」的方法论 | `skills/*/SKILL.md` | 任务收尾自动沉淀（`auto_learned`），或手写成常驻资产 |
| **架构** | 影响输出质量与形态的关键变动 | 本 README「架构演进」 | 每步讲清「为什么必须这样」，不记流水账 |
| **方法** | 怎么确认能力真在起作用、怎么不跑偏 | 「能力的契约」+ `self-verification` 技能 | 契约、不变量、自证规程 |

沉淀要**防污染**：任务书句式不进长期记忆、本任务的具体结论不进长期记忆、方法论技能里混进
本次任务的文件名/路径就整条作废（见「能力的契约」第 2 节）。

### 一条贯穿始终的原则：断言是常驻价值，脚本是消耗品

做测试用的一次性脚本（`_eval_*.py`、`tools/verify_*.py`）拿到结论就该退休——它们绑死了那一次
评测的路径与任务，换台机器跑不起来，留着只会让人误以为「上次过了 = 现在也对」。所以顺序是
**先把脚本守的断言抽成常驻的文档 / 技能 / 记忆，再让脚本退休**。这条也是测出来的：真删过几批，
也真发现过一份「README 声称存在、实际从没入库」的测试文件。取舍判据见「能力的契约」第 5 节。

## 架构演进

按时间顺序记录**影响输出质量与架构形态的关键变动**（bug 修复不在此列，见各自 commit）。
每一步都是后一步的地基：先省出上下文，才能跑得快；先有调度，才能谈效率。
这些变动是被什么驱动的，见上一节《它是怎么一步步训出来的》。

### 第 1 步：单 Agent 打磨（10-11，`a0944df`…`824e873`）

初始版本确立骨架：本地 Ollama 优先（零 API 费用）、工具调用、Skill 自动注入、零依赖单文件 Web UI。
随后集中打磨交互——思考过程展开、回溯导航、上下文压缩入口、token 精算与圆环计量条。

### 第 2 步：上下文治理（10-11，`394124e`、`45f1471`）

35 个工具全量下发约 4.3K tokens/轮，小模型撑不住。三件套把它压到常规轮次约 1.7K：

1. **工具按需下发**——核心工具常驻（读写文件/跑命令/找文件/查记忆/记笔记/取技能用法），
   其余按任务关键词命中才发 schema，只列名字，`find_tools` 现取用法；
2. **Skill 摘要注入**——只给开头几节；
3. **接力简报**——多步任务只传「计划 + 各步摘要 + 产出文件」，第 N 步不背负前 N−1 步的工具输出。

同时把上下文窗口提到模型上限（256K），技能目录与记忆同步瘦身。

### 第 3 步：部署与配置工程化（10-11 → 10-12，`14aad6a`…`d1675bd`）

换台电脑 clone 下来即可跑：`config.yaml` 变成不含绝对路径的纯通用模板，本机专属配置走
`config.lanrun.yaml`（gitignore）；`models.json`（API Key）不入库，仓库放空模板；
本地模型自动探测上下文长度并写好参数；新增 `tools/bench.py` 性能基准（读 Ollama 计时字段，横向可比）。

### 第 4 步：任务可见性（10-12，`a650029`…`5e47b97`）

**任务事件总线**：所有思考/工具/回复事件进 SSE 总线，发起连接断开任务不死，
网页刷新后可接管续播完整过程。任务台账记录状态、耗时、token 与费用、产出文件。
配套：用量卡悬停明细、语言漂移治理（每轮末尾中文提醒 + 严格 provider 的 system 上提合并）。

### 第 5 步：长材料规程 Skill 化（10-12，`7cc7acc`…`207e063`）

读大量素材后强制「清单 + 成文前自检」的末端提醒，从系统提示内联重构为 `long-material` skill
（含元数据路由），系统提示不再常驻这份规程。

### 第 6 步：多 Agent 架构（Batch A–D，本批提交）

单 agent 升级为多 agent：**任务在 agent 之间接力流转**，不是「在 LLM 之间流转」。

- **`agentforge/dispatcher.py`**：本地「决策模型」把一句话请求拆成语义独立的任务、按能力维度指派
  执行模型、维护共享进度（做过什么/产出在哪/需要什么），把前置任务的进度+产出整理成简报交接给下一个。
  拆解与指派失败自动回退规则编排——没有调度模型也能干活。
- **护栏**：`coding/math/writing/analysis` 四类任务永不派给决策模型；点名模型比场上最强者弱 ≥8 分
  时改派最强者并说明原因；纯闲聊（≤120 字且不含工具意图）才允许决策模型自己接，且可一键关闭。
- **并行波次**：独立任务同时跑（仅完全访问权限）；本地模型串行闸门（16GB 显存两个本地模型常驻会互挤）；
  同文件写入串行保护（`claim_write`），不同文件互不阻塞。
- **Provider 层**：OpenAI 兼容 / Anthropic / Ollama 三家统一形状，内部历史转严格 provider 格式
  （dict→JSON、补 `tool_call_id`、system 上提合并），支持 SSE 流式。
- **在严格 Provider 上跑通（Batch D 挖出的坑）**：本地 Ollama 对消息形状一律容忍，在线 provider
  要么直接 400、要么静默跑歪。下面每一条都是真实跑崩后定位并修掉的，不是预防性设计：
  - **语言提醒曾以 system 贴在消息末尾** → `System message must be at the beginning` 400。
    改为在 `_convert_messages` 里把**所有 system 收拢、合并成开头唯一一条**再发出；不改成
    `user` 角色——实测那样模型会去「回复」这条提醒，反而打断干活。
  - **上下文压缩会重建消息**，丢掉 DeepSeek 要求原样回传的 `reasoning_content`、以及 `role=tool`
    必须配对的 `tool_call_id` → 长任务跑到中途又 400。`context.py` 补了 `rehydrate_reasoning()`
    （按工具调用指纹「名字+参数」回填，找不到就保持原样、绝不张冠李戴）与「重建 tool 消息只改
    `content`、其余字段全留」。
  - **最阴的一个——SSE 中文乱码**：OpenAI 兼容流的 `Content-Type: text/event-stream` 不带 charset，
    `requests` 于是把编码认成 ISO-8859-1，`iter_lines(decode_unicode=True)` 按 latin-1 解码 →
    中文正文与**工具参数**（文件路径、搜索词）整段坏掉（`写作.txt` → `åä½.txt`），agent 读不到文件、
    搜索全 miss、只能反复空转，而界面看不出任何异常。本地 Ollama 的原生 `/api/chat` 是
    `application/x-ndjson`（走 bytes）不受影响——**本地跑绿 ≠ 在线 provider 跑绿**。改为
    `decode_unicode=False` + `raw.decode("utf-8", "replace")`。
  - **空轮次假成功**：思考模型偶尔返回「无 tool_calls 且正文为空」的一轮，原先被当任务完成
    （界面 `task_done files=[]`，实际零产出）。改为连续空轮次 ≤2 次时注入「上一轮没有输出」提示
    并继续，超过 2 次报 error——不再假成功。
  - **决策模型私自缩小任务范围**：把「通读素材并覆盖写入 outline.md」改写成「仅做分析，不执行
    文件写入」，执行者照 goal 干活就不写文件。`DISPATCH_SYSTEM` 明令「**绝不缩小任务范围**：用户
    要求的产物（文件名/路径/格式）必须原样出现在 goal 里」。
  - 顺带一个路由口径隐患：`router.py` 的候选池 `all_avail` 取的是 catalog 里 `available` 的模型，
    **包含没勾选的**——只要 `allow_paid_upgrade=True`，自动选型就可能挑到一个根本没勾选的付费模型。
    已用 `allow_paid_upgrade: false` 收口（关掉后候选池会先过滤掉 `paid`），但这个口径要留意。

### 第 7 步：记忆分层与技能元数据（本批提交）

- **记忆分层**（`memory.py` 重写）：借鉴 TencentDB Agent Memory 的 L0~L3 思路做单用户本地简化——
  L1 原子事实 / L2 项目约定 / L3 用户偏好，注入时按任务类型决定检索深度：
  抠技术细节的任务优先 L1（路径、端口、版本这类可精确执行的信息），常规对话优先 L3/L2。
  旧格式记忆行自动就地推断层标签，无需迁移。
- **技能元数据与沉淀**：SKILL.md frontmatter 支持路由元数据；任务收尾自动沉淀可复用技能。

### 第 8 步：工具层升级（本批提交）

- **`impact_of` 影响路径分析**（`tools/graph.py`）：零依赖静态扫描，定义处与引用处分开列出，
  改动前看清波及范围。
- **`task_notes` 任务草稿纸**（`tools/notes.py`）：`keep_recent_tool_results` 只保留最近几条原文，
  40+ 轮任务里第 10 轮查到的关键信息到第 30 轮已「失忆」。任务笔记每轮从磁盘现读现注入
  （≤2000 字尾部），压缩碰不到它——查到的发现永远在场，先查笔记再决定要不要重查。
- **联网工具的来源等级**（`tools/web.py`）：`web_search` 只用来找入口，输出头打
  `[搜索摘要 · 转述 · 未核实]`；`fetch_url` 打 `[实测 · 网页]`；新增 `fetch_json`
  （传 URL + `keys` 点分路径投影字段）打 `[实测 · API]`，把「打官方接口拿真实数据」变成
  一次调用能办的事。收尾还有系统侧核查兜底，见第 15 步。

### 第 9 步：防反复迭代（本批提交）

定位到简单任务反复打转的三个根因并逐一修复：记忆断层（压缩）、无轮次预算、无重复拦截。

1. **重复调用拦截**：只读工具（SAFE）按「名字+参数」指纹判重，任务内重复出现直接回放上次结果；
2. **轮次预算**：30 轮软预算（每轮催收敛）/ 60 轮硬上限（撤工具强制交卷）；
3. **保鲜**：`keep_recent_tool_results` 6→8，压缩摘要行 160→280 字符。

实测对比：同一个简单任务，修复前 28 分钟 / 68 次工具调用，修复后 18 秒 / 1 次调用（`t101213344526d9`）。
这些不变量原先由 `tools/verify_efficiency.py`（22 项断言）守着。它已按「`verify_*` 是一次性
批次证据、不是回归网」的约定退休（见「能力的契约」第 5 节），断言说的就是上面这三条。

**后续实测补强**（第四~八轮真实任务）：

- 效率修复对**检索密集型长链路任务**同样生效：第六轮调研 mattpocock/skills（含用 GitHub API
  复核 star 数据）1.7 分钟 / 10 次调用收敛（`ce9defc`）；
- 前端配合「合并呈现」：同一批工具调用在界面上合并成无框时间线组，连续调用不再刷屏
  （`7a04ecc`，见第 10 步）；
- 第八轮暴露的「谎报验证通过」是假收敛的另一种形态——轮次收敛了但结论是编的，
  由第 12 步的收尾验证闸门根治。

### 第 10 步：Web UI 结构性改版（本批提交）

- **思考过程改版**：不再出现喧宾夺主的框——无框浅灰小字，输出完成后排在正式输出之后，可点击折叠；
- **并行任务泳道**：多 agent 并行时逐泳道展示各自思考与工具卡；
- **任务管理侧栏**：台账可视化、清空弹窗勾选项与文件列表实时联动；
- **复制按钮**、权限说明悬停展开等交互细节（`e1451a9`、`9a886c1`）。

**后续八轮实测持续打磨**（`7a04ecc`…`2cdeb4b`，每轮反馈当天修完）：

- **工具调用时间线**：同一批调用合并成无框时间线组，spinner 转「对勾」；
  AI 头像行显示任务真实开始时间，接管别的页面发起的任务时也补齐用户气泡与计时；
- **产出文件卡片**：回复结尾的可点击卡片替代开头的文字清单行，点击直接打开文件或所在目录
  （`/api/open-folder` 放开相对路径），点击有反馈、无关联文件有兜底提示；
- **回看体验**：历史回看补工具条、回看时暂停贴底、接管任务自动切到聊天视图；
- **清空保护**：`skills/` 退出任务产出清理清单（曾被当任务产出误删，靠 git 才救回来）；
- **清空弹窗改成「逐条勾」**：每个类别（对话记录 / 过渡 · 中间文件 / 最终产出 / 被任务改过的文件 /
  任务留下的记忆）和它下面的每条明细都有自己的勾选框，且全部落在同一列上；类别与明细双向联动
  （明细全勾则类别自动勾上，勾掉一条变半选），点右侧箭头展开或收起明细。
  默认只勾「对话记录 + 过渡 · 中间文件（连同下面的明细）」，最终产出默认**保留但可以勾掉删**——
  删不删完全由勾选决定，界面文案也跟着勾选实时换（「将被删除 / 部分删除 / 全部保留」），
  不再写死「始终保留」。后端只接受清理快照里出现过的路径、以及属于本次已结束任务的记忆行号，
  越界一律跳过，接口不接受任意路径。
- **「读不到」不再冒充「没有」**：后端进程挂掉时，页面原先会把请求失败静默吞掉，
  再被 `|| []` 兜底渲染成「还没有记忆 / 还没有技能」，点清空更会谎报「还没有可清理的任务」——
  而侧栏明明还列着十几条历史任务（那是上一次成功拉取的数据）。数据其实好好躺在磁盘上，
  用户只会以为被清空了。现在所有只读接口走统一的 `apiGet`：连不上 / HTTP 报错 / 返回非 JSON
  都翻成人话异常；记忆与技能面板显示红色「读取失败 + 重试」而不是空态，侧栏顶部亮出
  「服务未连接，列表为上次数据」横幅，轮询失败时保留原列表不清空。
- 细节：提示行左对齐、输出加粗克制、加载圈与完成态区分。
- **最新一轮 UI 打磨（10-13）**：聚焦回复呈现的时序与状态一致性，全部集中在 `web/index.html`：
  - **头像行时间 = 本轮回复总耗时**：不再显示时钟，改为基于任务真实开始时刻累计，运行中实时跳动「执行中 XmYs」、整段收尾冻结为「完成 XmYs」，与子任务耗时区分开；
  - **工具条仅在整段回复收尾出现**：根因是 `complete` 事件早于整体收尾，多步任务里会提前挂出「复制/回答/朗读」；改为只在 `done` 用本轮最后一段正文挂一次，回答过程中不再出现（`stopped` 仍给部分回复挂工具条）；
  - **回复按生成顺序展示**：删去「思考挪到输出之后」的反转逻辑，思考过程自然留在正式输出之前，不再把结论提到前面；
  - **工具/技能调用状态文案与图标**：`use_skill` 识别为「技能」调用并展示被调技能名；工具=运行中「调用中」/完成「已调用」，技能=运行中「执行中」/完成「已执行」；运行中圆形 spinner、完成圆角矩形对勾。

### 第 11 步：输出与记忆治理（10-12，`1fa9791`…`2cdeb4b`）

八轮实测里另一类问题不涉及界面，而是「模型说的」与「实际发生的」对不上：

- **记忆防脏**：结构化任务书（`_is_task_brief`：长文本 + 「任务：/步骤：/验收」等结构词）
  不再被当用户偏好收进长期记忆；自动沉淀可一键关闭（`memory_autonote`）；
- **输出边界程序化**：结论纪律（涉及项目现状必须先查证才能写进回复）、如实总结
  （没验证的说未验证）、回复结构模板（结论先行 / 分节 / 结尾下一步），以及中文闸门——
  整合结果不是中文就强制回译。中文残留的根因是翻译桥接：弱中文模型被译成英文干活，
  产出英文摘要，靠提示词自觉堵不住，最后在输出边界程序化兜底。

### 第 12 步：可靠性工程——编辑护栏与收尾验证闸门（10-12，`58ae6e5`、`1d3d4e0`）

第八轮测试暴露本项目最危险的问题：修复任务的 3 次 `edit_file` 全部实际失败，
agent 没读工具返回的错误信息、也没重跑测试，就在总结里谎报「所有断言通过」，
最后靠人工独立复跑才当场戳穿。教训固化成三层防线：

1. **编辑护栏**（`tools/fs.py`，借鉴 Aider auto-lint）：`edit_file` / `write_file`
   保存后自动做语法检查（.py 用 `ast.parse`、.json 用 `json.loads`），
   失败自动回滚并把错误行号还给模型重试。边界很明确：**只查 `.py` / `.json`**（别的后缀不查），
   而且回滚**只针对「改已有文件」**——新建文件哪怕语法错也放行（新建的是草稿，没有「改坏」可言）；
   `edit_file` 另有两道前置闸：找不到待替换文本、或匹配到多处（有歧义），都直接报错且**一个字节都不动**；
2. **工具失败强呈现**（`loop.py`）：`[错误]` 结果自动追加系统注脚——必须先读错误修正重试、
   禁止无视失败继续、禁止未验证就声称完成；连续失败第 2 次起升级警告；
   前端工具卡新增红色「失败」态；
3. **收尾验证闸门**（`agentforge/verify.py` + `orchestrator._verify_gate`）：
   任务书里声明的验证命令（「验收：python tools/x.py」）由**系统亲自运行**
   （不经过模型工具调用），真实结果强制附进最终答复——**模型只有解读权，没有裁定权**。
   验证失败给一轮修正机会但报告照附；总结声称通过却全程没跑过命令的，
   追加「未经系统确认」声明。配套纪律：复用优先（先查证已有能力，禁止重复造轮子）。

自测 `tools/test_verify_gate.py`（73 项断言，覆盖命令提取与执行、谎报识别、产物核查、四条编排路径）。

### 第 13 步：运行期可靠性——上游守卫与常驻服务（10-13）

三件「不该让人操心的事」变成了代码：

1. **「读不到」不再冒充「没有」**。后端进程挂掉时，页面原先把请求失败静默吞掉再兜成空列表，
   于是「还没有记忆 / 还没有技能 / 还没有可清理的任务」三处一起说谎，而侧栏还列着十几条任务
   （那是上一次成功拉取的数据）。现在所有只读接口走统一的 `apiGet`，连不上/报错/非 JSON 一律
   翻成人话；记忆与技能面板显示红色「读取失败 + 重试」，侧栏顶部亮出「服务未连接，列表为上次数据」，
   轮询失败时保留原列表不清空。
2. **上游与自身都有人守**。本地模型的上游是 Ollama，长期不关机的机器上它可能被手动退出或升级时
   重启，本地模型就静默失效了——`agentforge/ollamaguard.py` 把它收成「探测 → 定位 → 拉起 → 等就绪」
   一件事，Web 启动、界面健康检查、常驻服务三处复用；`service.py` 则盯着 8787 端口，
   没人服务就补位拉起（**只补位不抢占、绝不杀进程**——杀进程会连带杀掉正在跑的任务）。
3. **常驻与自启从「手工配置」变成「仓库里的一步」**。以前「开机自启」只存在于这台机器的
   启动文件夹里——换台机器 clone 下来就没了，而启动项又无法入库（它必须写死本机的绝对路径）。
   现在由入口脚本 `start.bat` / `scripts/start.sh` 现场生成启动项，clone 完点一次就复现整套
   「随时打得开」，卸载留一条 `--remove-autostart`。

**第 14 步：入口收敛与「不占任务栏」（10-13）**

1. **四个看着重名的启动脚本收成一个**。`start-web`、`start-service`、`install-autostart`
   各有 `.bat` / `.sh` 一对，Windows 默认隐藏扩展名，于是根目录看着像四个同名文件，
   每次都要猜点哪个。现在根目录只剩 `start.bat`（Windows 双击），Unix 侧挪到
   `scripts/start.sh`（放子目录是为了不在 Windows 里跟 `.bat` 撞名）；开机自启不再单独一个脚本，
   由入口顺手登记。语义也简化成一句话：**点它，服务就一直开着**。
2. **服务彻底离开任务栏**。原来 `service.py` 拉 Web 服务用的是 `DETACHED_PROCESS`——
   实测它会给控制台程序**新开一个可见窗口**：一关掉 Web 服务就死，保姆又把它拉起来，
   于是任务栏里「关了又弹、关了又弹」。改用 `CREATE_NO_WINDOW` 后，服务自己没窗口，
   它拉起的任务命令继承隐藏控制台也不会弹黑框（实测父进程 `CREATE_NO_WINDOW` 时子进程
   `GetConsoleWindow()` 为 0；换成 `pythonw` 父进程反而会拿到可见窗口）。
   注意隐藏的只有 AgentForge 自己的这两个进程——任务里新开的命令行/程序照旧正常出现在任务栏。
   同一个坑也修在了 `ollamaguard._spawn`（退回 `ollama serve` 时）。

一个值得记下的坑：Windows 上不能用 `os.kill(pid, 0)` 探测进程存活——Windows 没有信号，
Python 的 `os.kill` 对非 CTRL_* 会直接调 `TerminateProcess`，「查一下你在不在」把人杀了。
已改用 `OpenProcess` + `GetExitCodeProcess`。另一个：venv 的 `python.exe` 可能只是转发器，
`Popen` 拿到的 pid 并不是真正占着端口的那个（实测 `web.pid=11500` 而监听者是 `19984`），
所以 `--stop` 走「记录 pid + 按端口扫占用者」双保险。

本轮的验证是逐条跑过、全绿的（Ollama 守卫 20 项、常驻服务 28 项、界面自动拉起 15 项），
但那些用例当时写在工作区临时目录、**没有随仓库留下**——留下的是上面这些结论本身。
仓库里可执行的自测见「能力的契约」第 5 节。

**第 15 步：检索的来源等级——一手来源优先（10-13）**

一次检索实测暴露的病：让它查 GitHub 上的 REA 项目，**流程全绿**（51 秒 / 3 次调用 / 全免费），
但结论里的数字**差一个数量级**——摘要写「Star 已达 **1w+**」，GitHub API 实测是 **17 万**；
「最近更新」写成「**2026 年 7 月**」，实际是当天。定性描述大致都对，定量与时效全错。
而它手里明明有 `fetch_url`，只搜了一次就下了结论。

根因不是工具坏，是**来源性质没有被区分**：「搜索摘要（转述）」和「一手来源（实测）」
在模型眼里长得一样。修法分三层，从「劝」到「拦」：

1. **说得清**（工具输出，`web.py`）。每个联网工具的输出头显式标注来源性质——
   `web_search` 打 `[搜索摘要 · 转述 · 未核实]`，`fetch_url` 打 `[实测 · 网页]`，
   新工具 `fetch_json` 打 `[实测 · API]`。`web_search` 的描述从「拿到结果后去读详情」这句
   **建议**升级为**硬约束**（搜到候选就必须抓至少一个一手来源再下结论），默认条数 6 → 8，
   末尾再补一句「这里的数字、版本、日期都不可直接写进回复」。
2. **给条路**（新工具）。`fetch_json` 把「打官方接口拿真实数据」变成一次调用能办的事：传 URL
   加逗号分隔的 `keys`（点分路径）就返回官方字段，不必让本地小模型自己拼 URL、自己读一大坨 JSON。
   核一个 GitHub 仓库，`https://api.github.com/repos/<owner>/<repo>` 一次调用就够。
3. **兜得住**（系统侧核查，`sources.py`）。只用过搜索、全程没抓过一手来源，而总结里又出现
   数字 / 版本 / 日期时，答复末尾由程序追加「转述 · 未经核实」声明，并逐条列出裸奔的数字——
   与收尾验证闸门同一思路：**模型只有解读权，没有裁定权**。它不改写正文、不阻塞收尾，
   只把证据等级说清楚。

方法论同时沉淀成技能 `skills/first-party-source/`（含常用官方 API 地图：GitHub / npm / PyPI），
让「先搜入口、再抓一手来源、才写结论」成为可复用的规程，而不是靠每条提示词重复叮嘱。

同轮还修了一类纯前端的「错觉」：任务结束后点开回看，界面上仍有东西在转圈 / 显示「执行中」。
顺着往下查，同一类问题一共有四处：

1. **工具组头卡在「调用中」**。回看历史的那条路径（`renderHistory`）只改了状态文本与样式，
   **从没把 `dataset.run` 清成 `0`**，而组头判定「运行中」正是看这个标志。
2. **组头自己的标志从不落定**。`toolHeadSummary` 只改文本与 class，不写 head 的 `dataset.run`——
   于是出现「文本说已调用、标志说还在跑」的自相矛盾状态。
3. **头像行永远显示「执行中 0m00s」**。头像行初始文案就是这四个字，冻结只发生在实时的
   `done` / `stopped`；回看历史不冻结，一条结束很久的回复就一直挂着「执行中
   （跟工具组头是同一类错觉）。现在回看时按任务台账里的真实耗时冻结成「完成 XmYs」。
4. **未执行的工具没有标红**。实时路径会给失败的调用加 `denied` 样式，回看路径漏了。

外加一道兜底：任何终态事件（`done` / `stopped` / `error`）之后，DOM 里仍标记为运行中的工具
一律落定为「未执行 / 中断」——任务已经结束，就不该还有东西在转圈。这四条一起锁进了前端回归
`tools/test_tool_panel.mjs`（21 项，用 jsdom 加载真实页面驱动 `renderHistory`，找不到 jsdom 会自动跳过）。

## 能力的契约：可观测、可验证、不自我污染

这一节不讲功能，讲**怎么确认这些能力真的在起作用、以及它们不会自己长歪**。
这些规矩原先只活在三份一次性验证脚本里——`_eval_novel.py`、`tools/verify_gen_logic.py`、
`tools/verify_layer_graph.py`。它们守的断言是常驻价值，但脚本本身绑死了那一次评测的路径与任务
（`_eval_novel.py` 里写着 `D:\AI_develop\project\novel`），换台机器就跑不起来，留着只会误导
「上次过了 = 现在也对」。所以把契约抽到这儿，脚本退休（git 历史里仍可取：
`git show <旧提交>:tools/verify_layer_graph.py`）。要重新跑这些断言，照下面四节重建即可。

### 1. 一次编排，怎么「看得见」

`POST /api/chat` 返回的是一条 **SSE 事件流**。按顺序读完，等于把「决策模型到底干了什么」复盘一遍，
不用猜它为什么这么答：

| 事件 | 含义 |
|---|---|
| `combo` | 由 planner 归并出的一条「复合任务」 |
| `route` | 这一轮交给谁：`auto` 是否自动选、`chosen` 与 `best` 及各自评分 |
| `dispatch` | 决策模型把一句话拆成 N 个子任务（`kind`、`deps`、是否 `parallel`、拆解理由） |
| `plan` | 执行计划摘要 |
| `assign` | 子任务 #i 派给哪个模型、扮演什么角色、为什么 |
| `bridge` | 交接说明（一个任务的产出交给下一个） |
| `conflict` | 多个任务要写同一个文件（写冲突预警） |
| `tool_start` | 每次工具调用：名字 + 参数 |
| `task_done` | 子任务 #i 结束：状态 + 产出文件 |
| `stats` | 每次模型调用的 tokens / tps / 花费（是否免费） |
| `history` | 完整消息历史（终态一并发回） |
| `complete` / `stopped` / `error` | 终态 |

两个实操要点：切到「自动配置所有模型」用 `POST /api/models {"action":"auto_config","scope":"best"}`；
自己写评测时**另起一个端口**（如 8795）跑 `serve(...)`，别去碰常驻服务的 8787，跑完 `shutdown()`。

### 2. 自沉淀的三条不变量（不自我污染）

自动沉淀（`autonote.py` / `autoskill.py`）最容易犯的错，是把「这次怎么做」当成「以后都这样」。
三条硬规矩：

1. **任务书句式不进长期记忆**。「必须先用 read_file 读完全文再动笔」「产出：写入 docs/x.md」
   这类是*这一单的指令*，不是用户偏好；凡「任务：/步骤：/验收」结构的任务书一律过滤。
   例外是强信号：「记住…」「以后…」这种用户明确要求保留的，哪怕长得像任务要求也照收。
2. **本任务的结论不进长期记忆**。带本机绝对路径的、提「本次任务 / 本次产出」的都是一次性的，
   写进记忆只会在下一个无关任务里误导人；该留的是用户偏好与项目约定。
3. **讲方法论的 skill 不得混入本次任务的专有内容**。skill 正文里一旦出现本次任务的文件名或
   绝对路径，**整条作废**——掺了细节的 skill 会在无关任务上误触发。这与 `self-extension` 里
   「自己写的 skill 一律放 `skills/learned/`」是同源规矩：一次性的东西别混进方法论。

### 3. 记忆分层与注入深度

每条记忆按语义粒度打层：**L1 原子事实**（路径 / 端口 / 版本）、**L2 项目约定**、
**L3 用户偏好**。`append` 自动判层，也可显式指定；旧格式（无层标签）的行会被就地推断层标签，
不需要迁移。注入按 `scope` 取：

- `facts`——把「事实与环境」排在「用户偏好」**前面**，抠技术细节时用（要的是可精确执行的信息）；
- `wide`——常规对话，偏好优先。

取哪种由 `loop.memory_scope()` 按任务文本决定：出现代码路径这类技术信号 → `facts`，否则 `wide`。

### 4. 技能资产的元数据契约（含「让位」）

SKILL.md 头部除 `name` / `description` 外，还认这几个路由与资产字段：

```
NAME / DESC / VERSION / WHEN / WHEN_NOT / KEYWORDS
---
正文
```

- **`WHEN_NOT` 是「让位」**：任务文本明显落在不适用的场景里时，该技能**不**自动命中——
  技能不只要能说「我什么时候用」，还得说清「什么时候别用我」。
- `WHEN_NOT: NONE` 视为「无特别不适用场景」（空）。
- `KEYWORDS` 里的标点 / 非法字符会被剔除，只留干净词（避免 `a:b`、`c[d]` 切出来的碎片）。
- 落盘后必须能经 `SkillRegistry` 原样读回：`brief()` 头部带「不适用：…」，`catalog()` 带版本号
  （形如 `doc-eval (v1.2)`）——否则「版本」就只是个装饰。

改这几处（记忆分层、技能注册、编排调度）时的操作规程，见 `skills/self-verification/`。

### 5. 仓库里的脚本：谁常住、谁是一次性的

判据只有一条：**这条断言三个月后还要不要跑。**

| 脚本 | 寿命 | 守着什么 |
|---|---|---|
| `tools/test_readcache.py` | 常驻（11 项） | 只读调用共享缓存：命中/回放计数/失效/容量/线程安全 |
| `tools/test_verify_gate.py` | 常驻（73 项） | 收尾验证闸门：命令提取与执行、谎报识别、产物核查、四条编排路径 |
| `tools/test_sources_gate.py` | 常驻（38 项） | 一手来源核查：搜索/抓取的识别、事实判据的召回与误报边界、三条件联动、闸门接入 |
| `tools/test_tool_panel.mjs` | 常驻（21 项） | 前端工具面板回看：组头/明细状态与图标、`dataset.run` 落定、头像行计时冻结（需 jsdom，缺了自动 SKIP） |
| `tools/bench.py` | 工具 | 本地模型性能基准（加载耗时 / 提示 / 生成 / 显存分布） |
| `tools/fastpull.py` | 工具 | 模型拉取通道测速与推荐、权重 sha256 体检、镜像整包重拉 |

`tools/verify_*.py` 是**批次证据**，不是回归网：为某一批改动而写，跑完即达目的，时过境迁就退休。
`verify_gen_logic.py`、`verify_layer_graph.py`、`verify_efficiency.py`、`verify_edit_guard.py`
都已按此退休——它们守的规矩留在上面这些节和「第 9 步」「第 12 步」里，脚本本身可从 git 历史取回。

于是新增验证时先问一句：**三个月后还要不要跑？** 要 → 写成 `tools/test_*.py` 常驻；
只是这一批的临时证据 → `tools/verify_*.py`，用它换一次结论，然后让它退休。

### 6. 外部事实的来源等级（一手来源核查）

数字是最容易悄悄错的东西：定性描述大致对，定量与时效可以全错，而读的人看不出来。
所以外部事实按**来源等级**处理，判据只有一句话：

> 这个数字，是我自己从官方来源读到的，还是别人转述的？

| 等级 | 来源 | 能不能引用 |
|---|---|---|
| **转述** | `web_search` 的摘要、第三方博客、聚合站 | 只能用来找入口，**不可引用** |
| **实测** | `fetch_url` 的网页正文、`fetch_json` 的官方 API 字段 | 可以 |

三道防线，从「劝」到「拦」：

1. **结论纪律**（`loop.py` 系统提示）：外部可核实事实必须来自一手来源；搜索摘要一律算转述，
   两者不得混用；只有转述可写时必须写明「据搜索结果，未经核实」。
2. **工具输出标注**（`web.py`）：输出头直接写明来源性质——`[搜索摘要 · 转述 · 未核实]` /
   `[实测 · 网页]` / `[实测 · API]`，让模型一眼看出哪条能引用。`web_search` 的描述也从
   「建议去抓详情」升级成硬约束。
3. **系统侧核查**（`sources.py` + `orchestrator._verify_gate`，配置项 `agent.sources_gate`）：
   三个条件同时成立，就在答复末尾追加程序写的声明——
   用过 `web_search`、全程没调过 `fetch_url` / `fetch_json` / `browser_snapshot`、
   总结里出现数字 / 版本 / 日期。命中的片段由程序逐条列出，模型动不了。

判定用的正则刻意宽松（允许指标词与数字之间夹几个中文字，比如「Star **数已达** 1w+」），
因为这一层是**提醒**而不是**拦截**：漏报的代价是有人照着错数字做决定，
误报的代价只是答复末尾多一段提示。两边不对等，所以宁可多报。

操作规程与常见官方 API 地图见 `skills/first-party-source/`。

## 本地模型性能基准

新增/更换本地模型后，想知道它在这台机器上到底跑多快，用 `tools/bench.py`：

```
python tools/bench.py                # 测所有已装模型
python tools/bench.py gpt-oss:20b    # 只测一个
python tools/bench.py --cold --tools # 冷加载 + 工具调用冒烟
```

它读的是 Ollama 自己的计时字段（不是掐秒表），所以横向可比：**加载s** 是模型进显存的耗时，
**提示tok/s** 是预填充速度（决定首字等多久），**生成tok/s** 是解码速度（决定读起来快不快），
末尾还会带上 `ollama ps` 的显存/算力分布，用来判断有没有被挤到 CPU 上。
