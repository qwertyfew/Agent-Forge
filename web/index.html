技能管理

Agent Skills 开放标准：技能是一份带 frontmatter 的 SKILL.md，任务命中它的 触发词时正文会被自动注入上下文。下面按来源分两块——提取得到的技能是 Agent 跑完任务后自己提炼沉淀的；安装得到的技能是放进 skills/ 目录的。 每张卡片展示技能的版本、触发边界（什么场景该用 / 不该用）与附带资源； 声明的「不适用」场景命中时会主动让位，避免关键词撞车导致的误加载。

能力缺口

由架构确定性记录、模型经由 report_gap 工具发起登记的缺失清单，不靠模型自报口径。 来源：模型调用不存在的工具（工具缺失）、工具预检判定任务需要的能力环境里没有 （能力缺失）、模型如实说明缺什么后主动登记（能力/技能缺失）、评测任务失败（评测失败）。 同类缺口合并计数，用来回答「该补什么工具 / 该沉淀什么技能」。

评测台

评测集（evals/tasks.yaml）是 harness 的标尺：每条任务喂给完整 agent 管线，判定全部走程序、零 LLM 调用——原文包含 → 归一包含 → 数值 → 关键词组 → 禁止内容 → 真跑命令核验，第一个失败的层就是失败归因（拆错了、答错了、产物坏了由此区分）。 每轮评测自动生成报告：时间、代码版本、模型、逐条表现与归因分布，用于持续优化 harness。 一轮全量评测要跑几分钟到更久（每条任务都是一次真实任务执行），期间可以切到别的栏目。

评测在后台线程执行，可切走；跑完会弹提示
