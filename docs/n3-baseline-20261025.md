## 附：59 次失败的逐类归因（2026-10-25 深夜复核）

### A. read_file 展示格式反噬——本轮最重要的发现，跨 3 条约 17 次

read_file 回执 = 头行（`路径  (N 行, 显示 x-y)`）+ `   1|内容` 行号前缀 + 尾部锚定行。
模型经常把它**当成原始文件内容**做二次处理：

- **f2（8/8 全挂）**：数出「8 行」= 1 条头行 + 7 行内容——把回执整段 splitlines 计数
- **a1（1 次）**：脚本把回执文本直接喂 `csv.DictReader` → 头行 + 行号前缀污染解析 → 总和 0.0
- **c7（7/8 挂）**：把展示文本（含头行）当内容排序写盘，产物开头就是 `D:/... (4 行, 显示 1-4)`

凡「读文件 → 程序化二次处理（计数/排序/解析）」的任务都会栽在同一处。
**候选 P31**：脚本内 read_file 支持 `fmt="raw"`（或提示词明确「脚本内处理内容用
内置 open()」——P24/P28 后脚本 cwd 已在交付区，裸 IO 读种子是安全的）。
与 P30 同族：都是「给人看的回执」被拿去「给程序用」。

### B. P19 gemma 退化循环：10 次

c1/a3/c8/a6/w4/c3 六条「连续 3 轮零输出」共 8 次 + o2/o3 两条超时
（4.2 万行/16.6 万字复读）。修法（repeat_penalty / num_predict）仍等拍板。

output/。镜像读让它能从根读到种子，强化了「根=工作目录」的错觉。
属模型心智模型与 P28 布局的残余摩擦，量小（2/8），继续观察。
