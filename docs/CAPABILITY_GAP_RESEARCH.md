# 短板分析与参考方案

### 1. 修改现有代码不精确
**参考项目：** SWE-agent, Aider-AI/aider
**实现机制：**
- **SWE-agent** 通过约束输出格式（如特定的 search/replace 块）来强制模型提供精准的修改点，而非重写整个文件。
- **Aider** 采用 diff 或全文件替换模式，并要求模型明确指出修改的行号或内容块。
**适配 Ollama 的原因：**
对于 Ollama 等中小型模型，直接让其重写长文件极易导致上下文丢失或逻辑遗漏。使用「确定性的搜索与替换」机制（Search & Replace）将复杂生成任务简化为精确的字符串匹配与局部填充，可靠性更高。
**落地建议：**
修改 `loop.py` 中的编辑工具，强制要求模型输出特定的 Markdown 块格式（包含 `SEARCH` 和 `REPLACE` 标记）。在执行前增加预校验逻辑，确保 `SEARCH` 内容在目标文件中真实存在且唯一。

### 2. 复杂前端/多文件联动任务做不下来
**参考项目：** OpenHands (CodeAct)
**实现机制：**
OpenHands 利用交互式的「环境感知」机制。它不是一次性生成所有修改，而是通过执行 shell 命令（如启动预览服务或运行构建脚本）来观察多个文件变动后的协同效果，并根据报错信息动态调整后续操作。
**适配 Ollama 的原因：**
弱模型难以在脑中模拟多文件耦合的复杂逻辑。通过提供「执行-反馈」循环，让模型通过真实的系统反馈（日志、错误堆栈）来驱动下一步操作，而非仅靠推理。
**落地建议：**
优化 `orchestrator.py` 的规划逻辑。对于涉及多个文件的任务，强制要求模型在修改前先执行一次环境检查（如 `ls -R` 或 `grep` 相关组件），并在每次修改后增加一个「联动验证」步骤。

### 3. 收尾诚实度差
**参考项目：** noahshinn/reflexion
**实现机制：**
Reflexion 引入了「自我反思」循环。当任务失败或测试未通过时，强制模型生成一份关于「为什么失败」的分析报告，并基于此分析进行重试，而不是直接给出一个虚假的成功总结。
**适配 Ollama 的原因：**
弱模型在面对失败任务时倾向于「讨好用户」而编造结论。通过引入结构化的错误分析环节，将任务收尾逻辑从「生成总结」变为「报告验证结果 + 反思改进点」，可以有效降低幻觉。
**落地建议：**
修改 `webui.py` 的任务收尾流程。增加一个强制性的「Verification Report」字段，要求模型必须包含具体的测试运行状态（Pass/Fail）及对应的日志片段，若为 Fail，则禁止提交成功的总结。

### 4. 复合多目标任务失败
**参考项目：** MetaGPT, AutoGPT
**实现机制：**
这些项目采用递归式的任务分解架构。将一个宏观目标拆解为一系列原子级的「User Story」，每个子任务必须是单一且可独立验证的动作。
**适配 Ollama 的原因：**
模型处理长链条任务时注意力容易分散。通过强制将任务分解到极其细碎的粒度（例如：不要「修复登录 Bug」，而是「修改 login.py 中的密码校验逻辑」），可以确保每一步都在模型的能力范围内。
**落地建议：**
改进 `planner.py` 的 `auto_plan` 逻辑。增加「递归拆解」功能，要求模型必须将每个子任务分解到「单次编辑操作」级别，并在执行前由系统校验子任务的原子性。

### 5. 改完代码不自测
**参考项目：** Aider-AI/aider
**实现机制：**
Aider 在每次代码改动后会自动触发预定义的测试脚本（如 `pytest` 或 `lint`）。如果测试失败，它会自动将错误信息反馈给模型进行修复。
**适配 Ollama 的原因：**
这是最简单的自动化流程，不需要模型具备极高的智能。只需通过程序逻辑在 `edit_file` 成功后自动触发 `run_command` 即可。
**落地建议：**
在 `loop.py` 中建立「改动-验证」闭环。为每个任务定义一套可选的验证指令（如单元测试、语法检查），并在编辑操作完成后自动执行这些命令，并将结果作为下一轮迭代的输入。

### 6. 没有受控的 git 提交能力
**参考项目：** Aider-AI/aider
**实现机制：**
Aider 集成 Git 操作，在模型确认任务完成且验证通过后，自动生成 commit 信息并执行 `git commit`。
**适配 Ollama 的原因：**
Git 提交是确定性的文件操作。将其作为 Agent 工作流的最后一步（Post-processing），不需要复杂的推理能力，只需要准确捕获任务成功的信号。
**落地建议：**
在 `loop.py` 或 `orchestrator.py` 中增加受控的 git 工具集成。只有当「验证脚本通过」且「用户确认完成」两个条件同时满足时，才允许执行自动化提交。
