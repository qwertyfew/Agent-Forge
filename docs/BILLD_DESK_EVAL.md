# billd-desk 项目调研报告

## 1. 项目概述
**billd-desk** 是一个基于 WebRTC 技术的开源远程桌面控制与游戏串流项目。它旨在提供一种低延迟、跨平台的远程连接解决方案，支持用户在不同设备（如电脑、手机、浏览器）之间进行流畅的屏幕共享和远程操控。

## 2. 解决的核心问题
- **高延迟问题**：利用 WebRTC 的 P2P 技术减少中间节点，降低画面传输延迟。
- **跨平台兼容性**：打破操作系统壁垒，支持 Windows、macOS、Android 以及 Web 端。
- **复杂网络穿透**：通过 STUN/TURN 服务器解决 NAT 导致的连接问题。
- **游戏串流需求**：针对高帧率要求的游戏场景提供优化的传输机制。

## 3. 技术栈
- **前端/UI 层**：Vue3 (用于 Web 端界面)、Flutter (用于移动端/桌面端客户端)。
- **核心通信**：WebRTC（负责实时音视频和数据传输）。
- **后端服务**：Node.js（提供信令服务器，协调连接建立）。
- **传输协议**：UDP（配合 WebRTC 实现低延迟）。

## 4. 核心功能
- **远程桌面控制**：支持远程操作电脑，包括鼠标和键盘模拟。
- **游戏串流**：优化后的高帧率画面传输，支持远程玩电脑游戏。
- **屏幕墙（Screen Wall）**：支持多设备同时连接或共享多个屏幕。
- **多端支持**：涵盖 Windows、macOS、Android 以及 Web 浏览器。

## 5. 架构设计
billd-desk 采用典型的 **WebRTC 信令架构**：
1. **客户端（Client）**：包含提供服务方（Host）和接收服务方（Guest）。基于 Flutter 开发以保证跨平台原生性能。
2. **信令服务器（Signaling Server）**：由 Node.js 构建，负责交换 SDP 信息、ICE Candidates 以及建立初始连接。
3. **P2P 传输层**：连接建立后，音视频数据直接在 Host 和 Guest 之间通过 WebRTC 进行点对点传输。
4. **NAT 穿透**：集成 STUN/TURN 服务，确保在复杂的家庭或企业网络环境中也能建立连接。

## 7. 适用场景与局限性
### 适用场景
- **远程办公**：在移动端控制办公室电脑。
- **远程技术支持**：协助用户操作复杂的软件界面。
- **游戏玩家**：在手机或低配设备上串流运行高配置电脑游戏。

### 局限性
- **网络环境依赖**：在极端对称型 NAT 或严格防火墙环境下，若无公网 IP 或 TURN 服务器支持，连接可能受限。
- **性能损耗**：高分辨率、高帧率的实时传输对 Host 端的编码能力有一定要求。

## 8. 同类项目对比
- **ToDesk / 向日葵**：商业软件，功能更成熟，但部分高级功能收费且存在数据隐私担忧。
- **RustDesk**：目前最流行的开源替代品，基于 Rust 开发，性能极强，但在 Web 端的支持和特定游戏串流优化上与 billd-desk 有不同侧重点。
- **Sunshine / Moonlight**：专注于极致游戏串流，但 billd-desk 在通用远程桌面和跨平台 UI 支持上更具综合性。
