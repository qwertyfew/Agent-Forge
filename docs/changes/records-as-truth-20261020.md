# 文件即记录：把「证据」从提示词里搬到磁盘上

**日期**：2026-10-20
**触发**：rerun28 交付物里 28 处引用、**0 处带行号**；此前 fill_section 被整节替换掉也没人知道。
用户的判断：操作文件本身就有记录，不该靠提示词反复要求，也不该靠返工；每次写盘落一个新文件，
覆盖就不可怕了。关键节点用文件保存下来，比一遍遍加闸门效率高。

## 1. 问题到底在哪

之前的「核查」分成两半，两半都靠不住：

| 环节 | 旧做法 | 失效方式 |
|---|---|---|
| 读侧证据 | 内存里的 `EvidenceLedger` | 一次 run 结束就没了；修正轮/重启失忆（rerun27 零交付） |
| 读侧证到什么程度 | 只记「文件读过」 | 读过 1-60 行也能引用第 300 行，凭空写也不会被拦 |
| 写侧防覆盖 | 回执里加警告、提示词要求用 append | rerun28 里 11 次 `fill_section` 各自「成功」，互相覆盖 |
| 行号要求 | 提示词要求「附行号」 | 模型整篇不写行号也能交付（rerun28 实测 0/28） |

共同点：**都要求模型在生成时保持自律**，而模型的自律不可测量、也不可复现。

## 2. 改成什么

一句话：**把「读过什么」和「写过什么」变成文件，核查只读文件。**

```
history/<任务目录>/
  _records/
    evidence.jsonl                # append-only：每条 read/write 一行（路径、行区间、sha、diff）
    citations.jsonl               # 每次写盘的引用核查结论（refs / with_line / inside / outside）
    versions/<path 扁平化>/
      0001-101530-3f9ac21b.md     # 第 1 版全文
      0002-101544-77c1de90.md     # 第 2 版全文（覆盖也留痕，谁也盖不掉谁）
```

三处改动对应三个失效点：

### 2.1 读侧：行区间是记录出来的

`read_file` 的回显头本来就是 `(N 行, 显示 a-b)`，`loop._record_evidence` 现在把它解析成
`ranges=[(a,b)]` 一并记进台账与 `evidence.jsonl`。于是引用核查从
「这个文件读过吗」升级成「**这一行你见过吗**」：

```
引用行号 src/mod.py:300 落在本任务实际读过的区间之外（读过：1-60）
——这一行你没有见过，请先 read_file 覆盖该行再引用
```

这是确定性判定，判据全部来自文件，不涉及语义猜测。

### 2.2 读侧跨轮/跨进程：台账从文件里读回来

`EvidenceLedger(recorder=...)` 构造时调 `hydrate()`，从 `evidence.jsonl` 重建「读过哪些文件、
读到哪些行」。于是修正轮换了 run、服务重启、另一个进程接手，看到的都是同一份事实。
上一轮靠调用方传对象（`run(ledger=...)`）解决的失忆，现在有了兜底：**即使没人传，也不会失忆**。

### 2.3 写侧：每次成功写盘 = 一个新文件

`fs.write_file / write_skeleton / fill_section / edit_file` 落盘后统一调
`Recorder.version()`：把这一版全文快照到 `versions/<扁平路径>/NNNN-<时分秒>-<sha8><后缀>`，
编号按文件递增、文件名带时间戳与内容 sha——同一秒连写两次也不会撞名。
回执里直接给出：

```
已覆盖文件 .../report.md（原 763 字符 → 现 2885 字符）
  版本：versions/evals__report.md/0002-101544-77c1de90.md（+42/-9 行）
```

覆盖从此不是「不可逆的破坏」，而只是「多了个版本」。所以：

- `fill_section` 的整节替换不再需要靠警告来防——数据本来就不会丢；
- 模型写错了不需要整篇重生成，用 `edit_file` 改几行，版本目录里能对比、能回滚；
- 人复盘时能逐版看「模型第几次写才写对」，这是评测时最缺的信息。

### 2.4 引用核查结论也落盘

每次写盘把 `refs / with_line / inside_read / outside_read` 追加进 `citations.jsonl`。
「这一轮交付物的证据质量」变成可聚合的数字，评测不必再靠人肉数引用。

## 3. 提示词怎么改（只在必要处）

不是为了约束模型，而是**告诉它"不需要自证"**，省掉它的自我防御动作：

- 删掉「唯一允许的写入是交付物」→ 中间/过渡文件照常写进产出目录（此前这条把模型的
  草稿逼成了「凭记忆直接写终稿」）；
- 写文件一节的标题从「三条硬规则（真的会拦）」改成「系统按记录核对，你不需要自证」，
  明确说：读过什么已经记在 `evidence.jsonl`，引用行号对不上会被拒收并回传真实区间；
- 保留「骨架先行」，但把 replace/append 的语义写进工具说明与回执，而不是靠模型记住。

## 4. 边界

- **记录不是产出**：`_records/` 在任务产出目录内，但不算交付物，不进 artifact 清点。
- **记录失败不影响主流程**：`Recorder` 的读写全部吞异常——记录是为了复盘，不是关键路径。
- **行区间校验只在「确实有区间记录」时生效**：老任务/CLI 直连没有区间记录时退回文件级判断，
  避免把「没记」误判成「没读」。
- **版本不做自动清理**：一次任务几十个版本、几 MB，先留着；将来按任务目录整体归档/删除。
