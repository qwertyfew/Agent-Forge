# 契约骨架：缺项在骨架阶段就露（2026-10-20）

## 问题：引用核查管不了「该写的维度写没写」

rerun29 的交付物是 8 行、21 处引用、13 处带行号且**全部落在真读过的区间**，
引用层面零缺陷。但任务书写明「至少覆盖这些对比点」共 10 项，它只写了 8 项：
会话恢复、skill 系统两项缺失，**没有任何一道关卡发现**。

原因是判定口径只有一种：写出来的内容对不对（引用能不能回源、行号见没见过）。
「该写什么」这件事从来没被程序化——它只活在提示词里，靠模型自觉。

## 做法：任务书的必填项变成文件里的结构，再变成收尾时的判定

三步，全部确定性，不新增提示词纪律：

1. **提取**（`skeleton.required_items`）：只认任务书里显式列举的两种形态——
   - `至少覆盖这些对比点：A、B、C`（冒号后的列举，按 `、，,;；` 切）；
   - `末尾附一节「X」`（引号里的指名小节）。
   提取不到两项就返回空列表，**完全不插手**：宁可不管，也不把普通句子当结构。

2. **铺骨架**（`skeleton.seed_from_brief`，在 `run_task` 一开始执行）：
   - 任务书自己声明了表格 → 表头照抄，每个必填项一行「（待填）」；
   - 否则每个必填项一个 `## 小节` + 一行待填占位。
   只在该路径**还不存在**时铺（模型已经动手的一律不碰）。建档记下每一行的初始
   内容，「填了没有」靠与建档内容比对，不靠长度阈值。

3. **判定**（两处，同一份清单）：
   - 运行中：`loop._owe()` 除了「文件在不在 / 本轮有没有更新 / 骨架填完没」，
     再判一次覆盖；契约闸门回灌时逐条给出原因，如
     `evals/gap-list.md（缺任务书要求覆盖的项：会话恢复（中断续跑）、skill 系统）`；
   - 收尾：`verify.find_artifact_issues(..., required=...)` 新增 `incomplete` 状态，
     命中给一轮修正，复查**重算覆盖**而不是看 mtime（补了两行但还缺两项时，
     mtime 早就变了——凭时间放行等于把覆盖核查退化成「写过就算」）。

覆盖判据是「这一项的字面出现在交付物里」，表格首列、小节标题、正文一句话都算；
归一化后做子串匹配，括注里的备选写法也认。**不强制**按某个标题分节——任务书要求的是
「覆盖」，格式要求由任务书自己定。

## 另一处：产出清单不再依赖「有人记得传 file_log」

`tasks.json` 里 rerun29 的 `files` 是 0，而交付物确实落盘了。原因：写盘发生在
**修正轮**，六处修正轮的 `agent.run(...)` 都没传 `file_log`，`Agent._file_log`
被置空，`ops_batch` 内层写盘的记录无处可去。

两条一起修：

- 六处修正轮 run 补 `file_log=`（`_verify_gate` 新增同名参数，四个调用点透传）；
- 收尾合并产出清单时，用记录层兜底：`Recorder.writes()` 从
  `history/<任务>/_records/evidence.jsonl` 读回每一次成功写盘，`artifact.from_records()`
  翻成产出记录，`merge()` 时工具记录优先、记录层补缺。

意义不在「补上这一次」，而在于：**产出清单的事实源从内存列表变成了磁盘记录**。
以后再有人漏传参数，清单也不会少。
