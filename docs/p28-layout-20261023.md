# P28 任务目录架构定型：交付区主写 + 读侧镜像（2026-10-23）

## 背景

用户定义的目标布局：`history/<任务时间戳>/` 区分任务，任务夹下 `record/` 存中间/过渡
文件、`output/` 存最终结果；模型生成文件直接放指定位置，读中间文件也从指定位置读。

改造前 `layout.py` 里这套约定已存在大半——但 `output/` 只是**收尾时镜像的案卷副本**，
交付物主写位置仍是「任务书点名路径落在工作区根」。两个实测缺口：

1. **读侧不对称**：写进 `record/work/` 的中间文件，六个读工具（read/edit/list/
   find/search）只解析到沙盒根，同路径读回来 = 「文件不存在」（2026-10-23 实测实锤）；
2. **P27 组合路径**：任务书分开点名目录零件与文件名（f1：「创建 reports/2026…新建
   一个空的 summary.md」），模型组合出的完整路径不在放行名单 → 被当成中间文件
   重定向，核验在交付区找不到（n1023/n1030 两次）。

## 设计

```
<工作区>/
├── （种子 + harness 自身文件，模型写不进未点名路径）
└── history/<任务>/
    ├── record/                  过程记录（evidence/versions/citations/run）
    │   └── work/                中间/过渡文件（架构强制落位）
    └── output/                  交付区：主写位置 + 模型的可见世界
```

| 规则 | 实现 |
|---|---|
| 写侧 | `resolve_for_write`：点名（WRITE_ALLOW：带目录路径 + 裸文件名 P23 + 组合路径 P27）→ `output/<声明路径>`；未点名 → `record/work/<路径>`；绝对路径不重定向、边界照旧 |
| 读侧 | 新增 `resolve_for_read`：`output/ → record/work/ → 根` 顺序取第一个存在的；`"."` → output/（list_dir 的默认视角）；六个读工具全部切换 |
| 命令 | `run_command` 默认 cwd 与 ops_batch 脚本 chdir 目标 = output/（种子发起时有界拷入：≤500 文件、单文件 ≤5MB、总量 ≤64MB、跳 .git/.venv/history/.agentforge 等；遍历用 `os.walk` 原地剪枝，不走 rglob 全树——见 `docs/changes/startup-latency-20261027.md`） |
| 对账 | 契约 `_owe`、`unfinished_file`/`required_missing`、`inline_verify_note`、收尾闸门 `run_verify_cmd` 全部指向 output/ |
| 评测 | `judge` 新增 `check_root` 参数，check 层在交付区执行；keywords 的 `expect.file` 双位置兜底（output/ 优先） |
| 回执 | 写盘落点区分两种文案：「任务书点名的交付：已写入交付区 output/」/「未点名：已作为中间文件存入 record/work/」 |

细节坑：**contextvars 不跨线程**——ops_batch 脚本线程里 `OUTDIR_CTX.get()` 恒为
None，必须在 `run()`（context 活着时）先取快照传进闭包。

## 验证

- 回归：全套件 ALL PASS（`test_layout` 新增 B2 组合路径、B3 读侧镜像共 8 条断言；
  `test_write_once` 索引总量哨兵 1800→1900，工具集累积踩线 +1.3%）；
- **p28a**（12 条吃布局用例）：**9/12**——f1（组合路径）首次通过；c1/c2/c3/c4/c6/
  f3/o3/w5 全过。3 条失败均非机制：f2（模型对展示文本计数，已知）、w3（模型空转
  crash，偶发）、w4（P25 判定读根未读交付区，当轮修复）；
- **p28b**：w4 PASS（修复验证）、w3 norm 失败（已知口径脆弱：答复保留「周五下午
  两点」，归一层要 `14:00`）；
- 10 轮 core-5 复跑（`--tag fixd`）读数见 `docs/fixd10-analysis-20261023.md`。

## 已知边界（记录在案，未处理）

1. 真实仓库任务的有界种子拷贝可能拷不全（>5MB / >500 文件 / 总量 >64MB）——工具读有根回退
   兜底，脚本内裸 IO 看不见未拷文件；
2. 产品模式下「用户工程文件被改名到 output/」的语义（交付物不再原地更新）——
   收尾镜像仍会拷根上改动；如需「任务结束回写原位置」是后续产品策略，待拍板；
3. w3/w4 类口径脆弱（P22 清单）与 f2 模型计数问题仍在，均非本架构问题。
