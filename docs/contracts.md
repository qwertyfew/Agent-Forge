## 修复清单：哪些是硬约束，哪些只是叮嘱

这一节回答一个问题：**已经修过的东西，现在是靠代码挡住的，还是靠"写下来提醒"？**
分清楚这个，才能判断"修了还出错"的风险在哪。它是《设计原则》那把尺子量出来的**结果账本**——
每一条历史问题落到哪一档、由什么防住，都记在这里，供后续改进对照（**这份清单是项目经验的一部分，
和代码一起演进，不是一次性的复盘**）。

### 强度分档

| 档 | 含义 | 破了会怎样 |
|---|---|---|
| **A 程序强制** | 代码里跑的检查 / 收口，模型碰不到也绕不过 | 不会发生（除非改代码） |
| **B 断言锁定** | `tools/test_*` 常驻回归把结论钉住 | 改回去立刻红，且说得出红在哪 |
| **C 提示词 / 技能** | 系统提示、SKILL.md 里的规矩 | **模型不听就什么都不会发生** |
| **D 作业纪律** | 记在 `.agentforge/memory.md`，靠人和 agent 遵守 | 需要事后复盘才能发现 |

A 与 B 常常成对出现：**A 是"挡"，B 是"证明挡得住"**。只有 A 没有 B，改动一次就可能悄悄退化；
只有 B 没有 A，测试锁的是别的东西。理想形态是「A + B」，下表里标 `A+B` 的都是这个状态。

### 三、仍然只有「劝」和「纪律」的（有意留在那儿）

| 事情 | 为什么不能架构化 |
|---|---|
| 结论纪律（`loop.py` 系统提示）：外部事实必须来自一手来源 | 这是模型**怎么做判断**的引导，判据本身依赖语义理解。能做的已做：闸门（A）兜底 + 工具输出标注。**保留 C 是因为它能让模型少犯，A 是因为它能兜住模型犯了** |
| 技能（`first-party-source` / `self-verification` / `long-material`） | 同上：技能是"方法论"，交给模型执行；技能文本里已写明"这条有系统侧核查兜底" |
| `.bat` 里外部命令写全路径 | 写作时的约定，没有运行时可检查的点 |
| 别在自己所在的工具 shell 里启停常驻服务 | 人的作业纪律，不是程序的输入输出 |
| 突变验证的备份顺序 | 能强制的是"改完必须重跑全量回归"这个动作；做没做只有人知道 |

**判断标准**：一件事如果"模型不做也不会出错"（因为程序挡着），那 C 层写不写都安全；
如果"模型不做就出错"，那它就不该待在 C 层——要么上移到 A，要么承认这里有个洞并写清楚。

## 能力的契约：可观测、可验证、不自我污染

这一节不讲功能，讲**怎么确认这些能力真的在起作用、以及它们不会自己长歪**。
这些规矩原先只活在三份一次性验证脚本里——`_eval_novel.py`、`tools/verify_gen_logic.py`、
`tools/verify_layer_graph.py`。它们守的断言是常驻价值，但脚本本身绑死了那一次评测的路径与任务
（`_eval_novel.py` 里写着 `D:\AI_develop\project\novel`），换台机器就跑不起来，留着只会误导
「上次过了 = 现在也对」。所以把契约抽到这儿，脚本退休（git 历史里仍可取：
`git show <旧提交>:tools/verify_layer_graph.py`）。要重新跑这些断言，照下面四节重建即可。

### 1. 一次编排，怎么「看得见」

`POST /api/chat` 返回的是一条 **SSE 事件流**。按顺序读完，等于把「决策模型到底干了什么」复盘一遍，
不用猜它为什么这么答：

| 事件 | 含义 |
|---|---|
| `combo` | 由 planner 归并出的一条「复合任务」 |
| `route` | 这一轮交给谁：`auto` 是否自动选、`chosen` 与 `best` 及各自评分 |
| `dispatch` | 决策模型把一句话拆成 N 个子任务（`kind`、`deps`、是否 `parallel`、拆解理由） |
| `plan` | 执行计划摘要 |
| `assign` | 子任务 #i 派给哪个模型、扮演什么角色、为什么 |
| `bridge` | 交接说明（一个任务的产出交给下一个） |
| `conflict` | 多个任务要写同一个文件（写冲突预警） |
| `tool_start` | 每次工具调用：名字 + 参数 |
| `task_done` | 子任务 #i 结束：状态 + 产出文件 |
| `stats` | 每次模型调用的 tokens / tps / 花费（是否免费） |
| `history` | 完整消息历史（终态一并发回） |
| `complete` / `stopped` / `error` | 终态 |

两个实操要点：切到「自动配置所有模型」用 `POST /api/models {"action":"auto_config","scope":"best"}`；
自己写评测时**另起一个端口**（如 8795）跑 `serve(...)`，别去碰常驻服务的 8787，跑完 `shutdown()`。

### 2. 自沉淀的三条不变量（不自我污染）

自动沉淀（`autonote.py` / `autoskill.py`）最容易犯的错，是把「这次怎么做」当成「以后都这样」。
三条硬规矩：

1. **任务书句式不进长期记忆**。「必须先用 read_file 读完全文再动笔」「产出：写入 docs/x.md」
   这类是*这一单的指令*，不是用户偏好；凡「任务：/步骤：/验收」结构的任务书一律过滤。
   例外是强信号：「记住…」「以后…」这种用户明确要求保留的，哪怕长得像任务要求也照收。
2. **本任务的结论不进长期记忆**。带本机绝对路径的、提「本次任务 / 本次产出」的都是一次性的，
   写进记忆只会在下一个无关任务里误导人；该留的是**用户偏好**（事实有工具现查、约定由架构保证）。
3. **讲方法论的 skill 不得混入本次任务的专有内容**。skill 正文里一旦出现本次任务的文件名或
   绝对路径，**整条作废**——掺了细节的 skill 会在无关任务上误触发。这与 `self-extension` 里
   「自己写的 skill 一律放 `skills/learned/`」是同源规矩：一次性的东西别混进方法论。

### 3. 记忆只放偏好

记忆里**只放用户偏好**（倾向 / 风格 / 习惯，如「回答先给结论」「产出文档一律简体中文」）。
另两类**不进记忆**：

- **事实与环境**（路径 / 端口 / 版本）：工具能现查，抄一份进来只会过期误导；
- **项目约定 / 流程规则**：由**架构**强制（程序 + 常驻断言）。写进记忆只是「劝」——
  模型没读到、或读到了没照做，这件事就不发生。

这条本身就是《设计原则》那把尺子的结果：判据是「**删掉这条记忆，测试会不会红**」——
会红，说明它本来就该待在架构里，不该躺在记忆里当叮嘱。

由此**取消了 L1/L2/L3 分层**（第 20 步）：`append` 不再判层、`prompt_block` 不再按任务类型
分配预算，一律取**最近的若干条**；旧格式行尾的 `· L1/L2/L3` 标记读到时**就地忽略**，
文件不用迁移。`remember` 工具也没有 `layer` 参数了。

### 4. 技能资产的元数据契约（含「让位」）

SKILL.md 头部除 `name` / `description` 外，还认这几个路由与资产字段：

```
NAME / DESC / VERSION / WHEN / WHEN_NOT / KEYWORDS
---
正文
```

- **`WHEN_NOT` 是「让位」**：任务文本明显落在不适用的场景里时，该技能**不**自动命中——
  技能不只要能说「我什么时候用」，还得说清「什么时候别用我」。
- `WHEN_NOT: NONE` 视为「无特别不适用场景」（空）。
- `KEYWORDS` 里的标点 / 非法字符会被剔除，只留干净词（避免 `a:b`、`c[d]` 切出来的碎片）。
- 落盘后必须能经 `SkillRegistry` 原样读回：`brief()` 头部带「不适用：…」，`catalog()` 带版本号
  （形如 `doc-eval (v1.2)`）——否则「版本」就只是个装饰。

改这几处（记忆、技能注册、编排调度）时的操作规程，见 `skills/self-verification/`。

只是这一批的临时证据 → `tools/verify_*.py`，用它换一次结论，然后让它退休。

### 6. 结论的来源等级（外部事实 + 本机事实）

「拿没查过的东西当查过的写出来」有两种表现，判据只有一句话：

> 这句话，是我自己从一手来源读到的，还是别人转述 / 我自己想出来的？

| | 转述（只能找入口，不可引用） | 一手来源（可以引用） |
|---|---|---|
| **外部事实** | `web_search` 的摘要、第三方博客、聚合站 | `fetch_url` 的网页正文、`fetch_json` / `github_search` 的官方 API 字段 |
| **本机事实** | 印象、同类项目的惯例 | 工作区本身：`list_dir` 看目录、`read_file` 看内容 |

数字是最容易悄悄错的一类：定性描述大致对，定量与时效可以全错，而读的人看不出来。
两道核查各三道防线，从「劝」到「拦」：

1. **结论纪律**（`loop.py` 系统提示）：外部可核实事实必须来自一手来源，搜索摘要一律算转述，
   两者不得混用；涉及本项目现状的结论必须先用 `list_dir` / `read_file` / `search_code` 查证——
   「列出 / 看看」这类要求问的是工作区**现在有什么**，不是让你回忆。
2. **工具输出标注**（`web.py`）：输出头直接写明来源性质——`[搜索摘要 · 转述 · 未核实]` /
   `[实测 · 网页]` / `[实测 · API]`，让模型一眼看出哪条能引用。`web_search` 的描述也从
   「建议去抓详情」升级成硬约束。
3. **系统侧核查**（`sources.py` + `orchestrator._verify_gate`）：

|  | 触发（全部由程序算，不看模型自报） | 出手方式 |
|---|---|---|
| **外部** · `agent.sources_gate` | 用过 `web_search` ＋ 全程没调过 `fetch_url` / `fetch_json` / `browser_snapshot` / `github_search` ＋ 总结里有量化措辞（数字 / 版本 / 日期）**或**时效性措辞（最近 / 月初 / 刚发布…，且总结确实在谈搜过的那个东西） | 答复末尾附「转述 · 未经核实」声明，命中片段逐条列出 |
| **本机** · `agent.local_facts_gate` | 任务问的是工作区现状（且不是在让它造东西）＋ 总结里在陈述现状 ＋ 全程没调过任何能读工作区的工具 | **先给一轮修正机会**（要求它 `list_dir` 看一遍再重写）；仍然没读才附「未经核实」声明，并在界面上标出是哪几项 |

外部那道是纯声明，本机那道多一层修正轮——「去读一眼」成本极低且一定做得到，
让系统替它把这一步做实，比事后加一句「请勿采信」有用。

外部那道的第二路（时效性措辞）是第 19 步补的：**「没写数字」不等于「有据」**。
「10 月初走红」一个阿拉伯数字都没有，可它和「star 已达 1w+」是同一个东西——
都是把别人摘要里的说法当结论写出来。之所以要求「总结与某次搜索的查询串有实词交集」，
是为了别把本地任务里的「最近改的那块代码」一起标上：用过搜索 + 谈的又是搜过的东西，
这时说「最近」才是在转述外部事实。

判定用的正则刻意宽松（允许指标词与数字之间夹几个中文字，比如「Star **数已达** 1w+」），
因为这一层是**提醒**而不是**拦截**：漏报的代价是有人照着错数字做决定，
误报的代价只是答复末尾多一段提示。两边不对等，所以宁可多报。
本机那道另加两个防误报的否决：**任务在让它造东西**时不出手（那种场合的文件名是它自己起的，
不是对现状的陈述），以及**任务书里已经提过的名字**不算凭空的现状。

操作规程与常见官方 API 地图见 `skills/first-party-source/`。
