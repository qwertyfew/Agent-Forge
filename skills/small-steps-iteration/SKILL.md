# 小步迭代 (Small Steps Iteration)

## 核心理念
复杂任务的失败往往源于试图一次性完成太多工作。小步迭代的核心是将大目标分解为“原子级”的、可独立验证的操作步骤，确保每一小步都建立在成功的基石之上。

## 操作规程

### 1. 任务分解 (Task Decomposition)
- 在动手修改代码前，先将用户需求拆解为具体的子任务列表。
- 每个子任务必须满足以下标准：
  - **原子性**：只解决一个核心问题。
  - **可验证性**：能够通过运行测试、检查日志或观察 UI 变化来确认成功。
  - **依赖清晰**：明确当前步骤依赖的前置步骤。

### 2. 执行与迭代 (Execute & Iterate)
- 按照拆解好的列表，一次只处理一个子任务。
- 严禁在未完成当前步骤的情况下跳到下一个步骤。
- 在每个子任务完成后，立即执行验证（见下文）。

### 3. 显式验证 (Explicit Verification)
- **不要假设成功**：仅仅代码没报错并不代表任务完成了。
- **验证手段**：
  - 运行单元测试或集成测试。
  - 启动服务并检查 API 返回值。
  - 查看日志输出确认逻辑分支进入正确路径。
  - 如果是前端修改，通过浏览器截图或检查元素状态确认 UI 正确。
- 若验证失败，必须先修复当前步骤，严禁在故障点上继续堆叠代码。

## 反面案例
❌ 一次性重构整个登录模块（涉及数据库、接口、加密逻辑和前端表单）。
✅ 先修改数据库模型 -> 跑测试确认模型正确；再修改后端接口逻辑 -> 跑集成测试确认数据交互；最后更新前端 UI -> 验证交互效果。

## 经验法则
- 如果一个步骤的修改点超过 3 个文件，或者涉及的操作难以用一句简单的测试脚本覆盖，请考虑进一步将其拆分为更小的子步骤。
