# Novel Writing（长篇小说写作）

## 核心原则：文件即真相

长篇（10万+字）远超单次对话的上下文容量。**一切设定与正文必须落盘**，
任何一轮对话只加载需要的文件。标准项目结构（建在工作区下，项目名做目录）：

```
我的小说/
├── bible.md            # 故事圣经：世界观、魔法/科技规则、时间线
├── characters.md       # 人物卡：姓名/外貌/性格/动机/口癖/人物弧光
├── outline.md          # 总大纲：三幕结构 + 每章一句话梗概 + 伏笔清单
├── progress.md         # 进度表：每章状态(草稿/修订/定稿) + 字数 + 备注
└── chapters/
    ├── chapter01.md
    ├── chapter02.md
    └── ...
```

## 工作流程

### 第 1 步：立项（与用户对齐）
问清或共同确定：题材、目标字数、视角（第一/第三）、基调、完结 or 连载。
然后用 `write_file` 建立 bible/characters/outline/progress 四个文件。

### 第 2 步：大纲
- 三幕结构：建置（25%）→ 对抗（50%）→ 解决（25%）
- `outline.md` 里每章一句话梗概 + **伏笔清单**（埋设章节 → 回收章节）
- 每章目标字数 = 总字数 ÷ 章数（网文单章 2000~4000 字较常见）

### 第 3 步：逐章写作（这是长跑，节奏最重要）
每章循环执行：
1. `read_file` 读 `outline.md` 中本章梗概 + `progress.md` 上一章结尾备注
2. 需要人物细节时才读 `characters.md` 对应段落（不要每次全文读）
3. 写正文 → `write_file` 存 `chapters/chapterNN.md`（两位数编号：chapter01）
4. 更新 `progress.md`（状态、字数、结尾钩子、本章埋/收的伏笔）
5. 每写 3~5 章用 `novel_stats` 核对进度

### 一致性维护（长篇最大杀手是前后矛盾）
- 人名、地名、称谓、能力规则以 `bible.md`/`characters.md` 为准，写作时拿不准就回读
- 发现矛盾：改 `bible.md` 源头，再 `search_code` 全局搜旧称谓逐处修订
- 时间线大事件记进 `bible.md`，避免"上周还是冬天"式硬伤

### 第 4 步：修订与合书
- 全部章节完成后逐章精修：开头钩子、结尾悬念、对话密度、节奏
- `novel_compile(dir_path="我的小说/chapters", output="我的小说/全书.md", title="书名")` 合书
- 用返回的各章字数检查是否均衡（单章差距 > 50% 通常意味着节奏问题）

## 跨会话续写

用户隔天回来续写时：先读 `progress.md` 恢复状态 → 确认写到第几章 → 继续。
**永远不要凭记忆续写，一切以文件为准。**

## 风格提示

- 展示而非陈述（show, don't tell）
- 对话推动情节，删除不承载信息的寒暄
- 每章结尾留钩子；中段警惕"幸福肥"（连续多章无冲突）
